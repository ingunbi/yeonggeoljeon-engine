# 07. 창 닫기와 종료 시 중단 저장

- 작성일: 2026-11-09
- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P0 · 단계: M0
- 선행: 기존 중단 저장 재사용. [12번](12.md)과 병행 가능하며 일반 저장 개편을 기다리지 않는다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [main.swift](../../../Sources/YeonggeoljeonEngine/main.swift)의 `AppDelegate.windowWillClose`는 타이머를 정지하며, 종료 메뉴는 `NSApplication.terminate`에 직접 연결된다.
- [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `quickSave`, `completeSuspendIfReady`는 저장 가능한 경계를 기다려 중단 저장한 뒤 타이틀로 이동한다.
- [SuspendSaveStore.swift](../../../Sources/YeonggeoljeonEngine/SuspendSaveStore.swift)의 `write`와 `resume`에는 단일 파일 교체, 잠금, 복원 준비 성공 뒤 소모가 이미 있다.
- 추가 범위는 운영체제의 종료 요청과 기존 중단 저장을 연결하는 엔진 편의 기능이다. 원작 종료 규칙을 새로 추정하지 않는다.

## 목적과 화면 흐름

1. 진행 중 창 닫기 또는 ⌘Q를 누르면 게임 안에 `중단 저장 후 종료 / 저장 없이 종료 / 취소`를 표시한다.
2. 저장을 고르면 `현재 행동을 마친 뒤 저장하고 종료합니다`와 예약 취소를 표시한다.
3. 행동·선택을 마칠 필요가 있으면 해당 입력을 계속 허용한다. 저장 완료 전에 창을 닫지 않는다.
4. 저장 실패 시 오류를 표시하고 같은 게임으로 돌아간다. 취소하면 대사와 남은 표시 시간을 보존한다.
5. 타이틀 등 보존할 진행이 없는 화면은 바로 종료한다. 저장 불가능한 오류·엔딩 상태에는 이유와 종료·취소를 표시한다.

## 구현 설계와 진입점

- 새 제안 타입 `TerminationCoordinator`가 요청 종류, 대상 창, 대기 상태, 승인 여부를 단독 소유한다.
- AppKit `applicationShouldTerminate`에서는 비동기 응답을 예약하고 저장 성공 후에만 종료 승인을 보낸다.
- `windowShouldClose`도 같은 조정기를 사용한다. `windowWillClose`는 종료 확정 뒤 정리 역할을 유지한다.
- 새 제안 열거형 `SuspendCompletionTarget`으로 기존 타이틀 이동과 앱 종료를 구분한다.
- `completeSuspendIfReady`의 경계 검사와 `host.suspendSnapshot`을 재사용하며 별도 임의 스냅샷을 만들지 않는다.
- 종료용 저장은 타이틀 뷰를 만들지 않고 검증된 파일 쓰기 성공을 조정기에 돌려준다.
- 확인창이 떠 있는 동안의 일시정지와 저장 경계까지 진행하는 대기를 분리한다.
- 연출 종료를 기다리는 중 ⌘Q를 반복해도 요청과 확인창을 중복 생성하지 않는다.
- 종료 확정 플래그는 한 번만 사용하여 승인 후 다시 확인창이 뜨는 재진입을 막는다.
- 연구 창 닫기는 캠페인 종료로 오인하지 않는다. 앱 종료 시 진행 중인 캠페인 창을 명확히 대상으로 삼는다.
- 독립된 진행 캠페인 창이 여러 개라면 한 중단 슬롯으로 모두 보존할 수 없다. 앱 전체 종료는 일단 보류하고 진행 창 목록을 안내하여 창별로 저장 또는 저장 없이 닫기를 선택하게 한다. 여러 창을 자동으로 연속 저장해 같은 중단 파일을 덮어쓰지 않는다. 창 닫기 승인은 해당 창에만 적용한다.

## 저장·호환·오류·취소

- 기존 별도 1칸과 이어하기 성공 후 소모 규칙을 유지한다. 종료 전용 다중 퀵 슬롯은 만들지 않는다.
- 현재 중단 파일 덮어쓰기 의미를 확인 문구에 포함한다. 일반 슬롯과 원작 저장은 변경하지 않는다.
- 저장 경계가 선택 완료를 요구하면 선택 입력을 허용하고, 불명확한 시간 제한으로 강제 종료하지 않는다.
- 파일 권한·공간·잠금 오류에는 종료를 거부하고 기존 파일과 실행 중 게임을 보존한다.
- 대기 취소는 종료 요청만 철회한다. 이미 확정된 게임 행동이나 난수를 되돌리지 않는다.
- [34번](34.md)의 비활성 일시정지와 함께 쓸 때 저장 대기와 정지가 서로를 기다리지 않게 한다.
- 강제 종료나 전원 차단까지 보호한다는 안내는 하지 않는다.

## 완료 기준

- [ ] 창 닫기와 ⌘Q의 세 선택이 같은 결과를 내며, 연속 요청으로 저장·종료가 두 번 실행되지 않는다.
- [ ] 이동·책략·적 턴 중 요청은 기존 안전 경계에서 저장되고, 선택 중 요청은 선택 입력을 가로막지 않는다.
- [ ] 쓰기 실패를 주입하면 창과 진행이 유지되고 이전 중단 파일도 읽을 수 있다.
- [ ] 취소 전후 대사 내용·남은 시간·선택·난수가 동일하며, 저장 뒤 재개는 중단 파일을 한 번만 소모한다.
- [ ] 실제 AppKit 창 닫기·⌘Q 검증을 고정 입력 검사와 별도로 기록한다.
- [ ] 여러 진행 창에서 앱 종료를 요청해도 다른 창을 조용히 닫거나 한 중단 슬롯에 연속 덮어쓰지 않는다.

## 작업 순서

1. 종료 조정기 상태 전이와 단일 요청 정책을 합성 테스트로 고정한다.
2. 기존 중단 저장 완료 동작을 분리하고 앱·창 종료 진입점을 연결한다.
3. 오류·대기 취소·비활성 창 조합을 검사한 뒤 실제 창 입력을 확인한다.
4. 사용자 안내를 갱신하고 [08번](08.md) 재개 검증에 종료 경로를 추가한다.

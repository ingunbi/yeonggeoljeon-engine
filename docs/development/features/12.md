# 12. 저장 관리와 일반 저장 내구성 개선

- 작성일: 2026-11-09
- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P0 · 단계: M0
- 선행: 기존 공통 저장 메뉴. [07번](07.md)과 병행하며 F3 확장 저장의 안전한 토대를 제공한다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [OriginalSettings.swift](../../../Sources/YeonggeoljeonEngine/OriginalSettings.swift)의 `OriginalSaveSlots.write`는 진행 JSON과 제목·날짜 JSON을 각각 원자적으로 쓴다.
- `OriginalSaveSlots.entry`는 라벨을 읽지 못하면 본문이 있어도 nil을 반환한다. 중간 쓰기 실패 위험은 정적 분석이며 실제 손상 확인으로 단정하지 않는다.
- [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `presentSlots`는 일반·중단·자동·원작 저장과 파일 불러오기를 같은 목록에서 제공한다.
- [SuspendSaveStore.swift](../../../Sources/YeonggeoljeonEngine/SuspendSaveStore.swift)는 메타데이터와 상태를 한 파일로 저장하며 성공 후 소모 규칙을 이미 구현한다.
- 새 범위는 일반 저장의 통합 교체·복구와 저장 폴더 접근이다. 중단 파일의 반복 복원 기능은 추가하지 않는다.

## 목적과 화면 흐름

1. 공통 목록에 `저장 폴더 열기`와 일반 저장에만 적용되는 `백업·복구`를 제공한다.
2. 슬롯마다 `비어 있음 / 정상 / 메타데이터 손상 / 진행 읽기 실패 / 미지원 버전`을 구분한다.
3. 복구 가능한 슬롯은 마지막 정상본의 제목·시각을 보여주고 현재 파일을 보존한 뒤 복구한다.
4. 일반 저장 수동 백업은 대상과 저장 위치를 사용자가 정하며 성공·실패를 같은 화면에 알린다.
5. 원작 슬롯은 계속 읽기 전용이고, 중단 저장은 단일 소모형임을 목록에서 구분한다.

## 구현 설계와 데이터

- 새 제안 타입 `NativeSlotEnvelope`에 형식 버전, 제목, 저장 시각, 진행 payload를 함께 둔다.
- 구체 버전 번호는 구현 때 명시적으로 확정한다. 새 봉투를 현행 `OriginalCampaignResume.format == 1` 파일처럼 위장하지 않는다.
- 새 제안 타입 `NativeSlotInspection`으로 파일 없음과 각 읽기 오류를 구분하여 UI에 전달한다.
- 메모리에서 전체 인코딩과 유효성 검사를 마친 뒤 같은 디렉터리의 임시 파일을 원자적으로 교체한다.
- 교체 전 기존 정상본을 검증하고 슬롯별 마지막 정상본 1개를 보존한다. 실패한 새 데이터로 백업을 덮지 않는다.
- 동시 실행에서 슬롯 저장·복구·백업이 충돌하지 않도록 파일 단위 잠금과 중복 요청 거부를 설계한다.
- `OriginalSaveSlots`의 읽기 경계에서 새 통합 형식과 기존 본문·라벨 쌍을 모두 판별한다.
- 기존 저장 조회만으로 파일을 이주하지 않는다. 사용자가 다음 저장을 확정할 때 새 형식으로 쓰고 원본 쌍을 보존한다.
- 예전 라벨이 없어도 유효한 본문을 확인하면 `제목 정보 없음`으로 복구 후보를 제공한다.
- 자동·전투 시작·이전 빠른 저장은 기존 불러오기 의미를 유지한다. 새 저장 쓰기 대상 확장은 별도 결정한다.
- `presentSlots`의 메뉴 진입에서 디렉터리 실패를 조용히 닫지 않고 원인과 재시도를 보여준다.
- 폴더 열기는 실제 저장 루트 계산을 재사용한다. 사용자 지정 저장 경로도 같은 위치로 연결한다.

## 저장·호환·오류·취소

- 호환 판별은 진행 payload의 `OriginalCampaignResume.read` 검증과 파일 크기 제한을 유지하도록 확장한다.
- 지원하지 않는 미래 버전을 무시하고 덮어쓰지 않는다. 파일 보존과 지원 버전 안내를 우선한다.
- 구형 빌드가 새 저장을 읽은 뒤 확장 정보를 버린 채 덮어쓰지 못하도록 읽기·쓰기 거부 또는 별도 새 슬롯 경로를 검증한다.
- 백업·복구 범위는 일반 저장이다. `suspend.json`을 백업 목록에 넣거나 성공 후 소모한 파일을 복원하지 않는다.
- 원작 세이브에는 쓰기·이름 변경·백업 교체를 수행하지 않는다.
- 손상 파일은 사용자 확인 없이 삭제하지 않는다. 복구 취소는 어떤 파일도 변경하지 않는다.
- 원자적 교체는 두 파일 불일치를 줄이는 수단이며 전원 장애에서 무조건 보존된다는 보장은 하지 않는다.
- 이주·권한·공간·잠금 실패의 각 단계에서 기존 정상본 또는 복구본이 유지되는지 확인한다.

## 완료 기준

- [ ] 새 통합 저장과 기존 본문·라벨 쌍을 모두 읽고, 조회만으로 기존 파일이 바뀌지 않는다.
- [ ] 본문 있음·라벨 없음·라벨 손상·본문 손상·미지원 버전을 빈 슬롯과 구별한다.
- [ ] 인코딩·임시 쓰기·백업·교체 실패를 주입해 정상 저장 보존과 오류 안내를 확인한다.
- [ ] 일반 저장 마지막 정상본 복구가 가능하며 복구 전 손상 파일도 보존된다.
- [ ] 중단 파일은 백업 대상에서 제외되고 성공 후 1회 소모가 그대로 동작한다.
- [ ] 지정 저장 경로의 폴더 열기, 중복 저장 요청, 복구 취소를 실제 메뉴에서 확인한다.

## 작업 순서

1. 기존 형식 합성 fixture와 단계별 실패 주입 검사를 먼저 작성한다.
2. 통합 파일·호환 읽기·잠금·정상본 보존을 구현한다.
3. 공통 메뉴 상태 표시·폴더 열기·백업·복구를 연결한다.
4. 격리 저장 경로에서 이주와 [07번](07.md)·[08번](08.md)의 저장 회귀 검증을 진행한다.

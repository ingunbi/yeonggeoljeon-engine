# 15 출전 준비 점검

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P1
- 개발 단계: M2
- 선행조건: F2 편성·책략 조건 조회
- 기준일: 2026-11-09

## 목적과 현재 구현

출전 직전에 선택 누락과 준비 부족을 알아보기 쉽게 한다. 현재 [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `presentParty`는 후보와 남은 선택 수를 표시하고 바로 출전을 확정한다.

## 사용 흐름과 화면

1. 편성 화면의 선택이 바뀔 때 준비 상태를 갱신한다.
2. ‘점검’에서 필수 조건과 권고를 분리해 확인한다.
3. 사용자가 지정한 주력 장수 누락, 선택 부대의 회복 수단, 가득 찬 소지품을 표시한다.
4. 항목을 누르면 해당 장수의 정보로 이동한다.
5. 권고는 무시하고 출전할 수 있으며, 원본의 필수 조건만 실제 출전을 막는다.

## 구현 범위와 데이터

- 제안 타입 `PartyReadinessIssue`는 코드, 심각도, 대상 인물 ID, 이유, 연결할 화면을 가진다.
- [OriginalParty.swift](../../../Sources/YeonggeoljeonEngine/OriginalParty.swift)의 `OriginalPartySelection`과 `confirm`이 실제 편성 규칙을 소유한다.
- `prepareSelection`에서 병력 초기화가 일어날 수 있으므로 초기화 전의 부상 상태를 출전 경고에 재사용하지 않는다.
- 회복 담당은 병과 이름으로 추측하지 않고 배운 책략과 도구에서 확인한다. 배치 전 MP를 알 수 없다면 ‘회복 가능 확정’으로 쓰지 않는다.
- 주력 장수는 사용자가 지정한 목록이며 자동 추천을 강요하지 않는다.
- 36번 프리셋을 쓰지 않아도 점검 기능을 사용할 수 있게 한다.

## 저장과 호환

주력 장수 ID는 회차별 F3 확장 데이터에 저장한다. 점검 결과는 저장하지 않고 현재 선택에서 다시 만든다. 이전 저장의 주력 목록은 비어 있으며 기본 강제 출전은 원본 규칙에서 읽는다.

## 예외와 취소

현재 참가할 수 없는 주력 장수는 ‘미선택’ 대신 ‘참가 불가’로 구분한다. 인원이 남았다는 이유만으로 원본이 허용하는 적은 인원 출전을 금지하지 않는다. 점검 창 취소는 선택을 바꾸지 않는다.

## 완료 기준

- [ ] 강제 출전과 원본 인원 규칙을 정확히 구분한다.
- [ ] 원본이 허용하는 편성을 권고 때문에 막지 않는다.
- [ ] 초기화된 병력을 오래된 부상 상태로 경고하지 않는다.
- [ ] 회복 수단과 참가 불가 사유가 현재 자료에 맞다.
- [ ] 점검·닫기 반복으로 출전 확정이나 VM 진행이 발생하지 않는다.

## 작업 순서

편성 상태 투영 → 점검 규칙 → 권고·필수 표시 → 주력 목록 저장 → 강제 출전·소수 편성 검증 순서로 구현한다.

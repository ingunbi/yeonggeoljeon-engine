# 33 상점 장바구니와 여러 개 구매

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P2
- 개발 단계: M2
- 선행조건: 13 소지품 투영, 37 물품 보호, F5 명령 경계
- 기준일: 2026-11-09

## 목적과 현재 구현

여러 장수에게 회복품 등을 나누어 살 때 반복 선택을 줄인다. 현재 [OriginalShop.swift](../../../Sources/YeonggeoljeonEngine/OriginalShop.swift)의 `OriginalShopOperation.answer`는 물품·수령인별로 구매를 확정한다. [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `presentShop`이 각 질문을 연결한다.

## 사용 흐름과 화면

1. 방문 중인 상점에서 물품, 수량, 받을 장수를 장바구니에 추가한다.
2. 각 장수의 구매 후 소지품 여유와 총가격·잔액을 확인한다.
3. 전체 구매를 확정하면 항목 순서대로 기존 구매 규칙을 적용한다.
4. 도중에 조건이 달라지거나 취소하면 완료 항목과 미처리 항목을 구분한다.
5. 미처리 항목은 수정 후 다시 구매할 수 있다.

## 구현 범위와 데이터

- 제안 타입 `ShopPurchasePlan`은 상점 식별값, 행 ID, 물품 ID, 수령인 ID, 수량, 예상 비용, 각 행의 완료 수량을 가진다.
- 실제 반영은 기존 `answerShop` 경계와 거래 검사를 재사용한다. 돈·소지품을 UI가 직접 수정하지 않는다.
- 계획 확정은 정해진 구매를 실행하도록 승인하지만, 예상 밖 질문과 미지원 단계에서는 멈춘다.
- 초판은 구매만 묶는다. 일괄 판매는 지원하지 않아 보호 물품과 장비 손실 문제를 분리한다.
- 수량은 현재 재고 종류·소지금·각 장수의 8칸 한도로 제한하며 무한 수량을 허용하지 않는다.
- 중복 입력으로 같은 행이 재실행되지 않도록 행별 완료 수량을 기록한다.

## 저장과 호환

장바구니 초안은 세션 UI 상태로만 보관한다. 중단 저장은 진행 중인 한 거래를 완료한 안전 경계에서 처리하고, 저장되는 상태는 실제 거래 결과뿐이다. 미처리 장바구니가 저장되지 않음을 중단 전에 표시한다.

## 예외와 취소

각 항목 직전에 가격·보유금·빈칸·수령 자격을 재검사한다. 취소는 완료 거래를 되돌리지 않고 남은 거래만 중단한다. 오류 시 이미 반영된 돈과 물품을 완료 내역에 남기며 다시 구매할 때 중복 처리하지 않는다.

## 완료 기준

- [ ] 미리보기의 총비용·빈칸 계산이 실제 연속 구매와 일치한다.
- [ ] 도중 취소 후 완료 수량만 돈과 소지품에 반영된다.
- [ ] 연속 클릭·재진입으로 구매가 중복되지 않는다.
- [ ] 부족한 돈·가득 찬 소지품·상점 변경에 안전하게 멈춘다.
- [ ] 중단 저장 후 재개 시 완료 거래는 유지되고 미처리 거래는 자동 실행되지 않는다.

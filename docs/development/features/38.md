# 38. 자주 쓰는 책략과 도구 즐겨찾기

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 작성일: 2026-11-09
- 우선순위: P2 · 단계: M3
- 선행조건: [09 사용 불가 이유](09.md), 기존 책략·도구 명령 경로와 F2 조건 조회.
- 기준: [전체 목록](../../../BACKLOG.md), [공통 구조](../architecture.md), [검증 기준](../verification.md).

## 현행과 차이

- [OriginalBattleView.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattleView.swift)의 `commandMenu`는 공격·책략·도구·대기와 습득표를 제공한다.
- 같은 파일의 `openStrategies`, `openItemList`, `beginItemUse`가 세부 선택과 기존 확인을 소유한다.
- [OriginalStrategyOperation.swift](../../../Sources/YeonggeoljeonEngine/OriginalStrategyOperation.swift)와 [OriginalItems.swift](../../../Sources/YeonggeoljeonEngine/OriginalItems.swift)가 사용 조건·행동 소모를 적용한다.
- 추가 기능은 자주 쓰는 항목으로 가는 선택 단계를 줄이며 실행 규칙은 바꾸지 않는다.

## 목적과 화면 흐름

1. 책략 또는 도구 목록에서 해당 항목을 즐겨찾기에 등록한다.
2. 장수의 명령창 상단에서 즐겨찾기를 확인하고 순서를 바꾸거나 해제한다.
3. 항목 선택 시 기존 대상 선택 또는 전직 비교·사용 확인 화면으로 이어진다.
4. 못 쓰는 항목은 남겨 두고 전직·미습득·MP 부족·물품 없음 등의 이유를 읽게 한다.
5. 즐겨찾기 버튼을 한 번 눌렀다는 이유만으로 즉시 행동하지 않는다.

## 구현 범위와 진입점

- 신규 타입 제안 `OfficerFavorites`는 캠페인 실행 ID, 데이터 식별자, 장수 person ID, 순서 있는 행동 참조를 가진다.
- 행동 참조는 `strategy(abilityID)` 또는 `item(itemID)`로 구분하고 이름이나 메뉴 인덱스를 식별자로 쓰지 않는다.
- 도구는 개별 소지품 슬롯이 아닌 종류를 즐겨찾기한다. 수량은 현재 소지품에서 계산한다.
- 같은 종류를 여러 개 가지고 있어도 즐겨찾기는 한 번만 표시한다.
- `commandMenu`의 표시 순서와 기존 `runCommand(index)` 연결이 엇갈리지 않도록 행동 ID 기반 라우팅을 제안한다.
- 기존 명령 4개의 의미를 유지하며 즐겨찾기 행을 삽입한 뒤 index를 그대로 실행하지 않는다.
- 책략은 기존 `selectStrategy`, 도구는 `beginItemUse` 등 동일한 진입점으로 전달한다.
- 전직 도구의 비교·확인, 범위 효과 확인, 대상 선택을 우회하지 않는다.
- 사용 가능 사유는 09/F2에서 읽고 UI 자체의 병과·MP·소지품 규칙을 복제하지 않는다.
- 표시 개수 제한과 넘침 처리를 두되 설정된 항목을 조용히 삭제하지 않는다.

## 저장과 예외

- 즐겨찾기는 F3의 캠페인 확장 정보에 저장하며 일반·중단 저장의 해당 스냅샷과 원자적으로 함께 보관한다.
- 불러오면 당시 장수별 즐겨찾기로 복원한다. 새 캠페인에는 자동 복사하지 않고 현재 합류·소지·습득 여부를 매번 검사한다.
- 데이터 식별자가 다르면 이름이 같아도 다른 장수·책략에 연결하지 않는다.
- 이전 저장은 빈 목록으로 시작하고 알 수 없는 ID는 사용 불가로 표시하거나 명시적으로 정리한다.
- 전직·물품 소진 뒤에도 참조는 유지하며 사용 불가 이유가 갱신된다.
- 등록·정렬·해제는 확장 정보만 바꾸고 실제 장수·소지품·MP·행동·RNG는 보존한다. 원작 세이브에는 쓰지 않는다.

## 완료 기준

- [ ] 같은 장수의 즐겨찾기 순서가 일반·중단 저장 시점으로 복원되고 다른 캠페인·장수와 섞이지 않는다.
- [ ] 전직·MP 부족·물품 소진 상태에서 이유를 표시하며 잘못된 행동을 실행하지 않는다.
- [ ] 도구 동일 종류 여러 개, 건네기, 재획득 후 수량·참조가 올바르게 갱신된다.
- [ ] 대상 선택·전직 비교·기존 확인과 실제 비용 소모가 일반 명령 경로와 같다.
- [ ] 메뉴 삽입 뒤 공격·책략·도구·대기의 index 혼동이 없고 읽기 조회는 RNG를 보존한다.
- [ ] 이전 저장·잘못된 ID·다른 데이터 식별자와 실제 창의 넘침·키보드 선택을 검증한다.

## 작업 순서

1. 장수·행동 식별과 캠페인 확장 정보의 호환 형식을 정한다.
2. 기존 명령 라우팅을 안정적인 행동 ID로 연결한다.
3. 등록·정렬·빠른 선택과 09의 현재 상태 사유를 붙인다.
4. 합성 저장 호환·행동 동등성 검증과 실제 창 입력을 별도로 수행한다.

이 문서는 구현 계획이다. 기능 구현이나 테스트 통과를 의미하지 않는다.

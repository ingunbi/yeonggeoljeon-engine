# 14 장비 구매와 교환 전 능력치 비교

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P1
- 개발 단계: M2
- 선행조건: 13 전체 소지품 관리, F1 읽기 전용 투영, F2 능력 계산
- 기준일: 2026-11-09

## 목적과 현재 구현

물건을 누구에게 줄지 판단할 때 실제 능력 변화와 비용을 먼저 확인한다. 현재 [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `shopRows`는 가격·잔액·소지품을, `personDetail`은 현재 능력치를 보여준다. 거래 전후 비교는 별도 기능이다.

## 사용 흐름과 화면

1. 상점의 물품 또는 13번 화면의 소지품을 선택한다.
2. 받는 장수 후보를 바꾸며 현재 수치와 거래 후 수치를 비교한다.
3. 건네기에서는 주는 장수의 손실도 함께 표시한다.
4. 물품 설명, 소지품 여유, 비용, 변화 없음 여부를 확인한다.
5. 구매·건네기 확정은 기존 거래 흐름에서 수행한다.

## 구현 범위와 데이터

- 제안 타입 `EquipmentTransferPreview`는 원본 인물 값의 복사본, 거래 종류, 물품 ID와 양쪽 전후 능력을 가진다.
- [OriginalState.swift](../../../Sources/YeonggeoljeonEngine/OriginalState.swift)의 `stats`, `giveItem` 슬롯 규칙과 [OriginalCombat.swift](../../../Sources/YeonggeoljeonEngine/OriginalCombat.swift)의 능력 계산을 공유한다.
- 별도 장비 슬롯을 가정하지 않는다. 현재 공격·방어·이동 보너스는 각 해당 분류의 최댓값을 사용하므로 같은 종류를 더해서 계산하지 않는다. 원본 소지품의 순서와 실제 계산 규칙을 유지한다.
- 비교 항목은 공격·방어·이동력과 장비가 실제로 영향을 주는 능력으로 제한한다.
- 소모품의 효과를 장비 능력 상승으로 표시하지 않는다. ‘보유만으로 변화 없음’과 사용 효과를 구분한다.
- 실제 피해는 대상·지형·사기에 달라지므로 기본 능력 비교와 혼합하지 않는다.

## 저장과 호환

미리보기 값은 저장하지 않고 최신 상태에서 다시 계산한다. 실제 거래 결과만 기존 상태에 저장한다. 필드의 비교 사기 기준과 전투 조회의 현재 사기 기준을 화면에 표시한다.

## 예외와 취소

비용 부족·인벤토리 가득 참·거래 금지 시 수치 비교는 보여주되 확정 불가 이유를 표시한다. 불완전한 물품 수치표는 비교 불가로 처리한다. 후보 변경이나 취소는 돈·소지품·난수를 변경하지 않는다.

## 완료 기준

- [ ] 건네기에서 양쪽 능력 변화가 실제 완료 결과와 일치한다.
- [ ] 동일 물품 중복 보유와 첫 동일 ID 제거를 정확히 반영한다.
- [ ] 이동 보너스와 변화 없는 소모품을 구분한다.
- [ ] 거래 직전 상태가 달라지면 오래된 예측으로 확정하지 않는다.
- [ ] 반복 조회·취소 후 상태와 난수가 동일하다.

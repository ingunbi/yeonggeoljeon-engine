# 32. 클리어한 전투 연습 모드

- 작성일: 2026-11-09
- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P3 · 단계: M5
- 선행: [12번](12.md)의 저장 격리, F3 진행 식별, [08번](08.md)의 대상 전투 정상 시작·종료 검증. 모든 분기 완주가 필수 선행은 아니다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `battleStartSnapshot`과 `OriginalBattleStartResume.matchesSource`는 실제 캠페인 문맥에 연결된 첫 턴 상태를 검증한다.
- [OriginalBattle.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattle.swift)의 `OriginalBattleSession`은 원작 규칙을 복원한 전투 상태다.
- [OriginalBattleFlow.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattleFlow.swift)는 원작 턴·행동·캠페인 훅을 처리한다.
- 현재 개발 메뉴의 독립 검증 전투나 실험 규칙 `BattleSession`은 캠페인 당시 상태를 보장하지 않으므로 연습 모드의 기반으로 사용하지 않는다.
- 추가 범위는 실제 클리어 전투를 당시 시작 상태로 분리 실행하는 사용자 기능이다.

## 목적과 화면 흐름

1. 본편 메뉴의 `연습 전투`에 현재 저장에서 클리어한 지원 전투만 표시한다.
2. 전투를 고르면 당시 출전 장수·레벨·소지품·시작 조건과 `본편에 반영되지 않음`을 보여준다.
3. 확인하면 연습 표시가 있는 별도 화면에서 같은 원작 규칙으로 전술을 시험한다.
4. 승패 후 연습 결과를 보여주고 재도전·목록·본편 복귀를 제공한다.
5. 연습 도중 종료·중단 저장도 연습 영역으로 처리하여 본편 진행을 대체하지 않는다.

## 구현 설계와 데이터

- 새 제안 타입 `PracticeScenario`에 battle ID, 완료 사건 ID, 검증된 시작 상태 참조, 규칙·자료 버전을 둔다.
- 실제 캠페인의 첫 턴 경계에서 임시 시작 상태를 확보하고 전투 클리어가 확정되면 연습 대상으로 등록한다.
- 예전 저장에서 이미 지나간 전투는 적합한 시작 상태가 없으면 `시작 기록 없음`으로 처리한다. 현재 장수 수치를 과거 상태로 꾸미지 않는다.
- 새 제안 타입 `PracticeHostContext`는 별도 `OriginalCampaignHost`와 인물·RNG·부대·기록 소유자를 구성한다.
- 단순 전투 세션만 만들지 않고 해당 전투의 스크립트·턴 훅·퇴각·보상 처리 문맥까지 복원한다.
- 엔진 규칙은 `OriginalBattleSession`·`OriginalBattleFlow`를 재사용한다. 연습 전용 임의 승리·수치 보정은 넣지 않는다.
- 본편 객체를 참조하는 변경 가능한 인물 목록·소지품·설정 콜백을 공유하지 않는다.
- 전투가 끝나면 정해진 종료 경계에서 연습 결과를 확정한다. 다음 본편 장면으로 자동 연결하지 않는다.
- 연속 전투의 한 전투가 독립 시작 문맥을 갖지 못하면 지원 대상에서 제외하고 이유를 표시한다.
- [31번](31.md)의 독립 실행·자료 식별은 공유할 수 있으나 리플레이 구현 완료를 필수로 묶지 않는다.

## 저장·호환·오류·취소

- 연습 목록의 해금 정보는 F3와 함께 본편 저장 시점에 종속되며 과거 저장에 미래 클리어 정보가 유입되지 않는다.
- 연습 중간 저장·자동 저장·결과 기록은 별도 저장 루트와 형식을 사용한다. 본편 `slots`와 중단 파일을 호출하지 않는다.
- 연습 중단도 별도 1회 소모 파일로 설계하고 본편 중단 저장과 화면에서 구분한다.
- 본편은 연습 진입 전 상태를 그대로 보존한다. 연습 경험치·소모품·금·승패·보상은 되돌려 합산하지 않는다.
- 자료·규칙 버전 또는 시작 문맥 검증이 실패하면 연습을 시작하지 않고 본편으로 돌아간다.
- 시작 상태와 자료는 로컬에만 보관하며 원본 콘텐츠를 공개 테스트나 배포물에 포함하지 않는다.
- 취소·비정상 종료 후 복구에서도 마지막 본편 저장을 연습 파일로 오인하지 않는다.

## 완료 기준

- [ ] 검증된 실제 클리어 전투만 당시의 합법 시작 상태로 열리고 실험 규칙 전투를 사용하지 않는다.
- [ ] 연습 승리·패배·도구 사용·전직·종료 후 본편 인물·물품·금·RNG·전적이 진입 전과 같다.
- [ ] 연습 저장·불러오기·중단이 본편 일반·자동·중단 저장 파일을 변경하지 않는다.
- [ ] 스크립트·증원·승리조건이 대상 전투의 검증 경로와 일치하고 다음 본편 장면으로 넘어가지 않는다.
- [ ] 예전 저장·기록 없음·자료 불일치·비독립 연속 전투에 지원 범위와 이유를 표시한다.
- [ ] 실제 창의 본편 복귀와 격리 저장 검사를 정상 입력 검증과 함께 완료한다.

## 작업 순서

1. 초기 지원 전투를 정하고 [08번](08.md)에서 정상 시작·종료 문맥을 확인한다.
2. 시작 상태 수집·클리어 해금·독립 호스트 및 저장 라우팅을 구현한다.
3. 별도 메뉴·연습 표시·결과·본편 복귀와 중단 저장을 연결한다.
4. 모든 변경 가능한 상태와 파일의 격리를 확인한 뒤 지원 전투를 확대한다.

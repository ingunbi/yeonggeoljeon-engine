# 10. 전투 종료 보고서와 누적 전적

- 작성일: 2026-11-09
- 상태: 부분 구현 · 안정화 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P2 · 단계: M3
- 선행: 공통 F4 확정 이벤트, F3 확장 저장. [12번](12.md)의 호환·오류 정책을 따른다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [BattleResultLog.swift](../../../Sources/YeonggeoljeonEngine/BattleResultLog.swift)의 `BattleResultLog`는 현재 전투의 공격·책략·도구·퇴각을 최근 500건까지 보관한다.
- [OriginalBattle.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattle.swift)의 `suspensionState`는 이 기록을 중단 저장에 포함한다. 새 전투 세션은 새 기록을 가진다.
- [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `finishBattleLoop`는 승패·재시작·지도 반환을 처리한다.
- [OriginalParty.swift](../../../Sources/YeonggeoljeonEngine/OriginalParty.swift)의 `finishBattleForCarryover`는 승리 시 경험치 보너스를 반영한다.
- 추가 범위는 전투를 떠난 뒤에도 남는 요약과 누적 조회다. 현재 상세 로그를 다시 만드는 기능이 아니다.

## 목적과 화면 흐름

1. 전투 결과와 원작 보상 처리가 확정되면 간단한 종료 보고서를 열 수 있게 한다.
2. 전투명·결과·소요 턴·퇴각 장수·획득 경험치·확인된 보상을 보여준다.
3. 메뉴의 `누적 전적`에서 완료 순서로 보고서를 찾고 전투·결과로 좁혀 본다.
4. 기존 상세 행동 기록이 남아 있는 현재 전투에만 그 기록으로 연결한다.
5. 연속 전투에서는 진행을 방해하는 강제 긴 창 대신 짧은 알림과 나중 조회를 기본으로 한다.

## 구현 설계와 데이터

- 새 제안 타입 `BattleSummary`에 campaign ID, attempt ID, battle ID, 결과, 턴, 종료 순번과 장수별 요약을 둔다.
- 새 제안 타입 `BattleSummaryAccumulator`가 F4 확정 이벤트를 받아 계산하고 화면 콜백에서는 집계하지 않는다.
- 상세 로그 500건 제한과 독립적으로 누적하여 긴 전투에서도 앞부분이 요약에서 빠지지 않게 한다.
- 공격·책략 경험치와 승리 보너스를 구분한다. 레벨 변화만 보고 경험치 총량을 역산하지 않는다.
- 보상은 실제 확정된 금·물품·경험치 변화만 표기한다. 출처를 연결할 수 없는 변화는 미집계로 표시한다.
- 퇴각은 인물 ID 기준으로 집계하고 여러 원인 이벤트가 같은 퇴각을 중복 계산하지 않게 한다.
- `finishBattleLoop`에서 결과의 의미를 해석한 뒤 한 번 확정하되, 보상 처리가 끝나기 전에는 최종 보고서로 보관하지 않는다.
- 재시작은 새 attempt ID를 부여하고 이전 시도는 실패·퇴각 기록으로 구분한다. 같은 결과 콜백 재전달은 무시한다.
- 누적 승패는 보고서 목록의 파생 값이며 별도 숫자를 중복 저장하지 않는다.

## 저장·호환·오류·취소

- F3에 완료 보고서와 진행 중 집계기를 저장하여 일반 저장·중단 저장 모두에서 이력을 이어간다.
- 예전 저장에는 `이 저장 이전의 전적 없음`을 표시하고 현재 상태에서 과거 전투를 추정해 생성하지 않는다.
- 이전 저장을 불러오면 해당 저장 시점의 전적으로 돌아간다. 다른 분기 이력을 자동 합치지 않는다.
- 보고서와 캠페인 상태의 저장 경계가 같아야 하며 저장 재시도로 결과가 두 번 추가되지 않아야 한다.
- 전투 요약을 여닫거나 필터링해도 게임 상태·난수·보상을 변경하지 않는다.
- 기록 한도와 압축 정책은 F3에 따르되 제한에 도달하면 보존 범위를 표시하고 몰래 오래된 누적 수치를 바꾸지 않는다.

## 완료 기준

- [ ] 승리·턴 제한 패배·퇴각·연속 전투에서 올바른 결과와 턴을 한 번만 기록한다.
- [ ] 500건을 넘는 전투에서도 총 경험치·퇴각·확인된 보상이 실제 확정 변화와 일치한다.
- [ ] 승리 보너스는 일반 행동 경험치와 구분되며 같은 보고서에 중복 반영되지 않는다.
- [ ] 일반·중단 저장 후 보고서가 보존되고 과거 저장 복원 시 이후 전적이 섞이지 않는다.
- [ ] 예전 저장·기록 한도·조회 취소에서 안내가 명확하며 조회 전후 상태와 난수가 같다.

## 작업 순서

1. F4에 필요한 결과·보상 사건과 시도 ID 수명주기를 정의한다.
2. 집계기와 재시작·중복 방지 합성 검사를 만든다.
3. F3 저장을 연결하고 종료 보고서·누적 조회 화면을 붙인다.
4. [08번](08.md)의 정상 승리·패배·연속 전투 경로로 결과를 대조한다.

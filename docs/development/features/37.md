# 37 중요한 물품 보호 표시

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P1
- 개발 단계: M2
- 선행조건: 13 소지품 관리, F3 회차 확장 저장, F5 사용자 명령 경계
- 기준일: 2026-11-09

## 목적과 현재 구현

사용자가 지정한 물품을 실수로 판매·폐기하지 않게 한다. 현재 [OriginalState.swift](../../../Sources/YeonggeoljeonEngine/OriginalState.swift)의 `discardItem`은 첫 동일 ID를 제거하고, [OriginalShop.swift](../../../Sources/YeonggeoljeonEngine/OriginalShop.swift)의 판매는 선택한 소지 슬롯을 비운다.

## 사용 흐름과 화면

1. 소지품 상세에서 ‘이 장수의 같은 종류 물품 보호’를 켠다.
2. 보호된 물품에는 자물쇠와 적용 범위를 표시한다.
3. 판매·버리기 시 보호 해제를 안내하고, 명시적으로 해제한 뒤 다시 명령을 수행한다.
4. 전투 사용 보호는 별도 선택으로 기본 꺼짐이다.
5. 보호 설정은 13번 관리 화면과 기존 물품 메뉴에서 동일하게 보인다.

## 구현 범위와 데이터

- 제안 타입 `ProtectedItemRule`의 키는 인물 ID와 물품 ID다. 같은 장수의 동일 물품 전체를 보호한다.
- 슬롯 ID나 가상 개별 물품 UUID를 원본 인벤토리에 추가하지 않는다.
- 허용된 건네기에서는 보낸 쪽 규칙을 유지하고, 받는 장수에도 해당 물품 보호를 이어 붙인다. 안내에 이 동작을 명시한다.
- 보유 수량이 0이 되어도 사용자 보호 규칙은 남아 다음 획득에 적용한다. 사용자가 직접 해제할 수 있다.
- 규칙은 사용자가 시작한 판매·폐기·선택한 소비에만 적용한다. 시나리오의 강제 회수·소모·보상 교체·전직 결과를 임의로 막지 않는다.
- 보호를 실제 물품 실행 함수에 무조건 넣지 않고 명령 출처를 구분한 F5 경계에서 검사한다.

## 저장과 호환

보호 규칙과 사용 보호 옵션은 F3에 게임 상태와 함께 저장한다. 이전 저장은 보호 없음으로 읽는다. 오래된 저장을 불러올 때 이후 시점에 추가한 규칙을 섞지 않는다.

## 예외와 취소

같은 ID의 물품 여러 개가 있어도 모두 동일하게 보호한다. 메뉴를 연 뒤 보호 상태가 바뀌면 확정 직전에 다시 검사한다. 해제 안내 취소는 돈·물품·행동을 바꾸지 않는다. 원본 강제 처리는 정상 수행한 뒤 변경 사실만 알려준다.

## 완료 기준

- [ ] 상점 판매와 필드·전투 폐기에서 같은 보호 규칙을 적용한다.
- [ ] 동일 물품 중복·슬롯 이동·건네기 후 보호 의미가 유지된다.
- [ ] 기본 설정에서 전투 사용은 가능하고 사용 보호를 켜면 차단된다.
- [ ] 시나리오 강제 소모를 막아 캠페인이 정지하지 않는다.
- [ ] 저장 왕복과 과거 저장 복원에서 해당 시점 보호 상태만 남는다.

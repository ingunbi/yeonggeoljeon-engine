# 36 출전 편성 프리셋

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P2
- 개발 단계: M2
- 선행조건: 15 출전 준비 점검, F3 회차 확장 저장
- 기준일: 2026-11-09

## 목적과 현재 구현

자주 쓰는 장수 조합을 반복해서 고르는 수고를 줄인다. 현재 [OriginalParty.swift](../../../Sources/YeonggeoljeonEngine/OriginalParty.swift)의 `OriginalPartySelection`은 강제 출전 prefix, 후보, 정원, 선택 순서를 관리하며 프리셋은 없다.

## 사용 흐름과 화면

1. 편성 화면에서 현재 선택을 이름 붙여 저장한다.
2. 다른 전투에서 프리셋을 고르면 적용 가능한 장수와 불가능한 장수를 먼저 본다.
3. 강제 출전은 유지하고 프리셋 순서대로 현재 선택을 교체할 계획을 표시한다.
4. ‘적용’을 눌러 선택만 바꾸고, 실제 출전은 기존 출전 버튼으로 확정한다.
5. 프리셋 이름 변경·삭제와 적용 취소를 제공한다.

## 구현 범위와 데이터

- 제안 타입 `PartyPreset`은 UUID, 이름, 순서 있는 인물 ID 목록, 자료 식별값을 가진다.
- 적용 계획은 현재 `OriginalPartySelection`의 값 복사본에서 `toggle` 규칙으로 만든다.
- 강제 출전은 제거하지 않고, 현재 후보가 아닌 장수·중복 ID·정원 초과를 사유별로 구분한다.
- 원본 배치 슬롯과 좌표는 [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `confirmParty`가 결정한다.
- 적용은 물품 교환, 장수 소환, 출전 불가 상태 해제를 수행하지 않는다.
- 불가능한 후보를 임의의 다른 장수로 대체하지 않는다.

## 저장과 호환

프리셋은 F3의 회차 확장 데이터에 저장해 일반·중단 저장 상태와 함께 복원한다. 새 게임에는 자동으로 이전 회차의 프리셋을 가져오지 않는다. 이름 길이와 저장 개수에 상한을 두고 잘못된 인물 ID는 건너뛰며 알린다.

## 예외와 취소

적용 직전에 현재 선택 조건을 다시 검사한다. 취소는 기존 편성을 그대로 유지한다. 부분 적용 계획은 자동 확정하지 않고 제외된 장수와 남은 자리를 먼저 보여준다. 강제 출전이 프리셋에 없어도 유지한다.

## 완료 기준

- [ ] 고정 장수가 해제되지 않고 원본 정원을 넘지 않는다.
- [ ] 참가 불가·중복·초과 장수를 서로 다른 이유로 보여준다.
- [ ] 적용 취소와 실패 시 이전 편성이 보존된다.
- [ ] 프리셋 적용만으로 VM·지도·소지품이 바뀌지 않는다.
- [ ] 저장 후 복원에서 프리셋 순서와 이름이 유지된다.

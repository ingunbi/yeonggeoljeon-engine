# 40 마을 시설과 대화 상대 찾기

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P2
- 개발 단계: M3
- 선행조건: F2 이동 가능성 조회, F5 탐색 입력 경계
- 기준일: 2026-11-09

## 목적과 현재 구현

현재 마을에서 상점·출구·인물을 찾아 헤매는 시간을 줄인다. 현재 [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `walk`, `talk`는 원본 경로와 접촉 규칙을 사용한다. 목록에서 그 입력으로 연결하는 안내를 추가한다.

## 사용 흐름과 화면

1. 마을의 ‘주변 찾기’에서 현재 표시된 시설·출구·인물을 본다.
2. 항목을 선택하면 위치와 경로를 강조한다.
3. ‘이동’ 또는 ‘대화하러 가기’를 누르면 기존 경로 입력을 실행한다.
4. 도착 후 발생하는 대사·상점·선택은 기존 화면에서 직접 처리한다.
5. 다른 목적지를 선택하면 진행 중 이동 규칙에 따라 거절하거나 안전하게 전환한다.

## 구현 범위와 데이터

- 제안 타입 `LocalDestination`은 현재 지도 ID, 인물 ID 또는 명시적인 셀 좌표, 표시 이름, 도착 종류를 가진다.
- [OriginalExplorationInput.swift](../../../Sources/YeonggeoljeonEngine/OriginalExplorationInput.swift)의 `townCell`, `townActor`에 경로와 자격 판정을 맡긴다.
- 지도에 실제 존재하는 액터와 확인된 표식만 목록에 넣는다. 미래 이벤트로 등장할 인물은 제외한다.
- 시설 표식이 여러 셀에 걸쳐 있으면 명시적인 입구 셀을 선택한다. `townDestination`의 단일 표식 가정을 확장해 임의의 가까운 문을 고르지 않는다.
- 이동은 순간이동이 아니며 길이 막히면 기존 경로 실패를 표시한다.
- 목록 선택은 대사 선택지 응답이나 구매를 자동으로 확정하지 않는다.

## 저장과 호환

목록은 현재 지도에서 다시 생성하고 저장하지 않는다. 진행 중 이동은 기존 탐색 상태의 저장 규칙을 따른다. 최근 선택을 유지할 때 지도 ID와 대상 ID가 현재도 유효한지 검사한다.

## 예외와 취소

떠돌이 인물이 움직이면 실행 직전 경로를 다시 계산한다. 지도 변경·퇴장·이벤트 시작 후 오래된 대상은 폐기한다. 같은 이름의 인물은 위치와 인물 ID로 구분한다. 현재 정보가 불충분하면 시설명을 지어내지 않는다.

## 완료 기준

- [ ] 목록의 항목이 현재 지도에서 실제로 보이는 대상과 일치한다.
- [ ] 직접 클릭과 목록 이동이 같은 경로·접촉 결과를 만든다.
- [ ] 동적 인물 이동과 다중 입구를 잘못된 목적지로 연결하지 않는다.
- [ ] 목록 조회만으로 이동·이벤트·난수가 진행되지 않는다.
- [ ] 도착 후 선택지와 거래는 사용자 입력을 기다린다.

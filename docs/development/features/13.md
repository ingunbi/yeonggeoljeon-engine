## 목적과 현재 구현

누가 어떤 물건을 갖고 있는지 한 번에 찾고 기존 건네기 작업으로 연결한다. 현재 [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `presentExchange`는 주는 장수, 물품, 받는 장수를 차례로 고르는 흐름이다.

## 사용 흐름과 화면

1. 필드의 장수 메뉴에서 전체 소지품을 연다.
2. 물품명·효과 종류·보유 장수로 필터하고 장수별 8칸과 빈칸 수를 본다.
3. 물품을 선택하면 설명과 가능한 받는 장수를 표시한다.
4. 받는 장수를 고른 뒤 건네기를 확정하고 두 장수의 목록을 갱신한다.
5. 검색과 스크롤 위치를 유지해 다음 물품을 처리한다.

## 구현 범위와 데이터

- 제안 타입 `InventoryRow`는 인물 ID, 원본 슬롯 위치, 물품 ID, 현재 개수, 빈칸 수를 투영한다.
- 검색·정렬은 화면 순서만 바꾸며 원본 `itemIDs` 배열은 재정렬하지 않는다.
- [OriginalState.swift](../../../Sources/YeonggeoljeonEngine/OriginalState.swift)의 `OriginalPeople.giveItem`은 첫 빈칸에 넣고 주는 쪽의 첫 동일 ID를 비운다. 이 규칙을 유지한다.
- 실제 변경은 [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `exchangeItem`을 통한다.
- 전투 중 통합 조회는 읽기 전용으로 제공할 수 있지만 필드 건네기를 호출하지 않는다.
- 창고, 물품 복제, 자동 장비 배치는 만들지 않는다.

## 저장과 호환

소지품은 기존 인물 상태에만 저장한다. 검색어·필터는 세션 UI 상태로 두고 별도 캠페인 데이터를 요구하지 않는다. 보호 표시와 즐겨찾기는 각각 37·38번의 확장 데이터로 연결한다.

## 예외와 취소

확정 직전에 인물 참가 상태, 보유 여부, 상대 빈칸과 필드 입력 가능 여부를 다시 검사한다. 실패 시 어느 쪽 소지품도 바뀌지 않아야 한다. 같은 이름의 장수와 같은 종류 물품은 이름 대신 ID로 처리한다.

## 완료 기준

- [ ] 필터 결과의 개수와 실제 8칸 인벤토리가 일치한다.
- [ ] 정렬만으로 소지품 슬롯 순서와 전투 수치가 바뀌지 않는다.
- [ ] 가득 찬 장수에게 전달하면 물품 유실 없이 이유를 표시한다.
- [ ] 전달 성공 시 주는 쪽 1개 감소와 받는 쪽 1개 증가가 함께 반영된다.
- [ ] 취소·지도 전환·이전 저장 불러오기 후 오래된 행으로 전달하지 않는다.

## 작업 순서

전체 인벤토리 투영 → 검색·필터 → 기존 건네기 진입 → 상태 재검사와 실패 처리 → 중복 ID·가득 찬 인벤토리 검증 순서로 구현한다.

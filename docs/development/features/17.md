# 17. 예상 피해의 계산 근거 설명

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 작성일: 2026-11-09
- 우선순위: P2 · 단계: M3
- 선행조건: F1 읽기 전용 예측과 F2 공통 계산 규칙. 03의 선행 기능이다.
- 기준: [전체 목록](../../../BACKLOG.md), [공통 구조](../architecture.md), [검증 기준](../verification.md).

## 현행과 차이

- [OriginalBattle.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattle.swift)의 `attackForecast`는 피해·사기 감소·격파·반격 확률을 반환한다.
- [OriginalCombat.swift](../../../Sources/YeonggeoljeonEngine/OriginalCombat.swift)의 `physicalStrike`는 상성에 따른 방어 조정, 지형, 반격 감산, 최소값과 병력 상한을 순서대로 적용한다.
- 같은 파일의 `strategyStrike`는 저항·환경·정수 연산·성공 판정·흔들림을 처리한다.
- 추가 기능은 이 계산 순서를 읽을 수 있게 제공하며 별도 피해 공식을 만들지 않는다.

## 목적과 화면 흐름

1. 기존 피해 예측 옆의 상세 버튼을 누른다.
2. 공격자·대상과 현재 병과·레벨·사기·장비·지형을 확인한다.
3. 실제 계산 단계별 입력과 결과를 읽고, 확률 항목은 별도 영역에서 본다.
4. 상세를 닫으면 기존 대상 선택 상태로 돌아간다.
5. 원본 기준 값과 엔진 설명용 문구를 구분한다.

## 구현 범위와 진입점

- 신규 타입 제안 `CombatCalculationTrace`는 식별 정보, 순서 있는 단계, 최종값과 확률 설명을 가진다.
- 각 단계는 규칙 ID, 입력값, 적용된 정수 연산, 중간값을 기록한다.
- 실제 계산 커널에서 선택적으로 trace를 생산하거나 공통 순수 계산 결과를 반환하도록 확장한다.
- UI에 독립 수식을 복사하거나 최종값에서 기여도를 거꾸로 추측하지 않는다.
- 병과 상성은 방어 조정 단계로, 지형은 해당 곱셈·나눗셈 단계로 설명한다.
- 사기·장비는 공격/방어 계산의 실제 기여 위치에 표시하고 단순한 피해 가산값으로 제시하지 않는다.
- 반격 자체의 확률과 반격이 일어났을 때의 피해는 서로 다른 값으로 표시한다.
- 책략은 성공 시 피해 범위, 실패 시 효과, 성공 확률과 저항·환경 조건을 구분한다.
- byte/word 절단과 정수 나눗셈을 실제 순서대로 따르며 근삿값이면 근사라는 표시를 붙인다.
- 수치에 쓰인 원본 표·소스 오프셋의 분석 근거는 로컬 검증 자료에 연결하고 공개 문서에 실물 데이터를 복제하지 않는다.

## 저장과 예외

- 계산 trace는 파생 정보이며 일반·중단 저장에 넣지 않는다.
- 대상·날씨·지형·장비·사기·병력 변경 시 상세를 재계산한다.
- 원본 표 누락이나 미지원 효과에는 ‘근거를 계산할 수 없음’을 표시하고 가상의 분해를 하지 않는다.
- 현재 RNG 상태를 복사해 얻은 다음 판정 결과를 확정 예측으로 공개하지 않는다.
- 상세 조회 전후 실제 세션·RNG·기록은 동일해야 한다.
- 비공개 적의 능력치나 숨어 있는 보정의 존재를 상세 설명으로 노출하지 않는다.

## 완료 기준

- [ ] trace를 사용하는 경우와 사용하지 않는 경우 실제 커널 결과가 동일하다.
- [ ] 상성·지형·사기·장비 변화가 올바른 계산 단계에 나타난다.
- [ ] 최소 피해·남은 병력 제한·반격 감산·정수 절단 경계가 최종값과 일치한다.
- [ ] 책략 성공 확률·흔들림과 반격 확률을 확정 피해에 합쳐 표시하지 않는다.
- [ ] 상세 반복 조회 후 상태·RNG·이벤트가 동일하고 숨겨진 정보가 드러나지 않는다.
- [ ] 실제 창에서 긴 단계 설명과 기존 대상 선택으로의 복귀를 확인한다.

## 작업 순서

1. 실제 커널별 계산 순서를 문서와 합성 예제로 고정한다.
2. 공통 커널에서 trace를 생산하고 결과 동일성을 확인한다.
3. 예측 상세 패널과 상태 변경 갱신을 연결한다.
4. 합성 수치 경계와 실제 창 표시를 검증하며 원본 런타임 비교와 구분한다.

이 문서는 구현 계획이다. 기능 구현이나 테스트 통과를 의미하지 않는다.

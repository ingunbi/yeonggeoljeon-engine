# 34. 앱을 벗어났을 때 자동 일시정지

- 작성일: 2026-11-09
- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P1 · 단계: M1
- 선행: [07번](07.md)의 종료·중단 저장 요청 상태와 정지 소유권을 합의한다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `tick`은 60Hz 타이머로 호스트·연출을 진행하고 `suspendPromptActive` 동안은 멈춘다.
- [CanvasOverlay.swift](../../../Sources/YeonggeoljeonEngine/CanvasOverlay.swift)의 `setSuspended`는 대사 표시·자동 넘김·시간 제한의 남은 시간을 보존한다.
- [OriginalAudio.swift](../../../Sources/YeonggeoljeonEngine/OriginalAudio.swift)의 `fill`은 별도 오디오 콜백에서 음악 드라이버를 진행한다. 화면 타이머만 멈춰서는 소리 시간이 멈추지 않는다.
- [main.swift](../../../Sources/YeonggeoljeonEngine/main.swift)의 `AppDelegate`에는 앱 비활성·최소화에 따른 게임 정지 연결이 없다.
- 새 범위는 사용자 선택형 엔진 편의 기능이며 전투 규칙·배속·이동력의 변경이 아니다.

## 목적과 화면 흐름

1. 설정에 `다른 앱 사용 중 일시정지`를 제공하며 새 설정의 기본값은 켬으로 제안한다.
2. 다른 앱 전환이나 게임 창 최소화 시 대사·연출·시뮬레이션을 같은 경계에서 멈춘다.
3. 복귀하면 `일시정지됨` 표시와 기존 입력 초점을 복구한 뒤 자동 재개한다.
4. 사용자가 명시적으로 일시정지한 상태는 복귀만으로 풀리지 않는다.
5. 확인창이나 저장 대기 중에는 현재 상황을 알려 정지가 저장 완료를 영원히 막는 상태를 만들지 않는다.

## 구현 설계와 데이터

- 새 제안 타입 `PauseCoordinator` 하나가 `inactiveApp`, `minimizedWindow`, `userPause`, `savePrompt` 등 정지 사유 집합을 소유한다.
- AppKit 활성·비활성 및 창 최소화 알림은 조정기에만 전달하고 각 뷰가 독립 Bool을 뒤집지 않는다.
- 조정기가 `OriginalCampaignView.tick`, 기존 overlay, 전투 연출, 오디오의 유효 정지 상태를 함께 적용한다.
- `CanvasOverlayView.setSuspended`는 실제 정지 상태가 바뀔 때만 호출하여 중첩 사유 해제로 타이머가 일찍 재개되지 않게 한다.
- 복귀 시 벽시계 경과 시간을 시뮬레이션에 몰아서 반영하지 않고 남은 고정 단계부터 진행한다.
- 키를 누른 채 앱을 벗어나면 빠른 감기·방향키 상태를 해제하여 복귀 때 남은 키 입력이 새 명령을 만들지 않게 한다.
- 기본 음악 정책은 드라이버 상태를 유지한 무음 정지다. `stop`이나 재선곡으로 음악을 처음부터 틀지 않는다.
- 새 오디오 정지 경로는 `fill`에서 무음만 채우고 driver·chip 시간을 진행하지 않으며 기존 잠금 규칙을 지킨다.
- 창 간 이동은 앱 비활성과 구분한다. 연구 창의 포커스 변화가 다른 캠페인의 수동 정지를 해제하지 않는다.

## 종료 저장과 정지의 우선순위

- 종료 확인창은 게임을 멈추지만 확인 후 `안전 경계까지 진행` 단계는 확인창 정지 사유를 해제한다.
- 사용자가 종료용 저장을 확정했다면 조정기가 승인된 진행 대기 상태를 명시적으로 소유한다.
- 정지된 연출 때문에 안전 경계에 도달하지 못하면 종료 대기 UI에서 `저장을 위해 계속 / 취소`로 해결한다.
- 진행에 선택 입력이 필요하면 해당 선택창을 보여주고 복귀를 기다린다. 선택을 대신 결정하거나 숨겨진 자동 진행을 하지 않는다.
- 파일 쓰기·완료 알림은 시뮬레이션 틱의 재개를 기다리지 않는다. 저장 실패 시 종료 요청을 취소하고 정지 사유를 재평가한다.
- 대기 중 모든 상황을 포괄하는 전역 정지 Bool로 틱을 막는 구현은 사용하지 않는다.

## 저장·호환·오류·취소

- 설정은 `OriginalSettings`의 사용자 설정으로 저장하고 이전 설정에서 누락된 키의 기본값을 명시한다.
- 앱 비활성 같은 일시적 정지 사유는 게임 세이브에 저장하지 않는다. 이어하기 직후 실제 창 상태에서 다시 결정한다.
- 정지·재개는 난수·행동 소모·대사 확인을 발생시키지 않는다. 오디오 실패도 게임 진행 보존과 분리한다.
- 옵션을 끄거나 정지를 취소해도 남아 있는 다른 정지 사유는 유지한다.

## 완료 기준

- [ ] 대사 자동 넘김·이동·책략·일기토 중 앱 전환 후 복귀해도 남은 시간과 연출 위치가 보존된다.
- [ ] 최소화·앱 비활성·사용자 정지가 중첩되어도 마지막 해당 사유가 해제되기 전에 재개되지 않는다.
- [ ] 복귀 시 시간 몰아 진행·눌린 키 잔류·대사 자동 확인이 발생하지 않는다.
- [ ] 음악은 정지 위치에서 이어지고 음소거·효과음 설정을 임의로 바꾸지 않는다.
- [ ] 종료 저장 대기가 정지와 교착하지 않고 선택 필요·저장 실패·취소 경로에서 진행을 보존한다.

## 작업 순서

1. 정지 사유·종료 대기 조합 상태표와 합성 타이머 검사를 작성한다.
2. 단일 조정기에 AppKit 알림·overlay·호스트·연출을 연결한다.
3. 오디오 정지·키 상태 해제·설정 호환을 구현한다.
4. 실제 앱 전환·최소화와 [07번](07.md)의 종료 저장을 함께 확인한다.

# 29. 캠페인 여정과 선택 기록

- 작성일: 2026-11-09
- 상태: 부분 구현 · 안정화 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P3 · 단계: M4
- 선행: 공통 F4 확정 이벤트, F3 확장 저장. [28번](28.md)과 [39번](39.md)의 참조 기준을 공유한다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `choose`, `completeSelectedMap`, `confirmParty`는 캠페인 선택과 장면·출전 처리를 담당한다.
- [CampaignVM.swift](../../../Sources/YeonggeoljeonEngine/CampaignVM.swift)의 실행 상태에는 현재 진행 문맥이 있으나 사용자용 방문·선택 연표를 대체하지 않는다.
- [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `dialogueLog`는 뷰에 최근 표시 대사를 보관하며 여정이나 저장된 선택 이력은 아니다.
- 새 범위는 실제 경험한 사건의 연표다. 시나리오 전체 분기 도표나 정답 공략을 만들지 않는다.

## 목적과 화면 흐름

1. 메뉴의 `여정`에서 방문·합류·선택·주요 사건을 발생 순서로 확인한다.
2. 장·도시·사건 종류로 좁히고 항목을 선택하면 그때 확인한 내용만 읽는다.
3. 보관된 대사가 연결되어 있으면 해당 기록으로 이동하고 없으면 `대사 기록 없음`을 표시한다.
4. 최근 선택 3개는 [28번](28.md)의 이어하기 요약에서도 이용한다.
5. 미경험 분기·방문하지 않은 도시·미합류 인물은 비어 있는 미래 항목으로도 미리 노출하지 않는다.

## 구현 설계와 데이터

- 새 제안 타입 `CampaignJourneyEntry`에 campaign ID, 사건 순번, 종류, 장·장면 식별자, 관련 인물·도시와 대사 참조를 둔다.
- F4의 확정 사건에서만 생성하고 버튼 누름·화면 표시·미리보기 단계에서는 기록하지 않는다.
- 선택은 선택지 식별자와 확정한 항목만 기록한다. 선택하지 않은 문장이나 이후 분기의 결과를 저장하지 않는다.
- 도시 방문은 이동 요청이 아닌 실제 도착 완료에서 기록한다. 같은 방문의 재그리기·재개는 중복시키지 않는다.
- 합류는 출전 편성 선택과 구별하고, 실제 동료 상태가 바뀌는 확정 효과를 분석해 연결한다.
- 주요 사건은 지원되는 원본 효과와 근거가 확인된 매핑만 사용한다. 임의 스토리 요약을 생성하지 않는다.
- 새 제안 `JourneyReducer`는 사건 ID로 재처리를 방지하며 사건 순서는 벽시계 대신 진행 순번을 따른다.
- 대사 참조는 [39번](39.md)의 안정 ID를 사용한다. 조회 때문에 원본 스크립트의 미래 대사를 가져오지 않는다.
- UI용 문구는 현재 자료에서 읽거나 저장 시 경험한 짧은 설명을 로컬에 보존하고 공개 fixture에는 합성 문구만 쓴다.

## 저장·호환·오류·취소

- F3의 진행 종속 기록으로 일반·중단 저장과 같은 원자적 커밋에 포함한다. 독립 전역 연표를 두지 않는다.
- 이전 저장을 불러오면 해당 시점의 여정으로 돌아간다. 이후 선택과 다른 분기의 기록은 합치지 않는다.
- 전투 재시작에서는 그 전투 시도에 종속된 여정 범위를 시작 경계로 되돌린다. 실패 시도 통계는 [10번](10.md)에서 구분한다.
- 일반 저장 이전에 기록을 소급 생성하지 않는다. 예전 저장에는 `이 저장 이전의 여정 없음`을 표시한다.
- 기록과 본편 상태 중 한쪽만 저장되는 상태를 허용하지 않으며 F3 저장 실패 시 함께 실패 처리한다.
- 기록 상한은 공통 저장 제한에 맞춰 검증하고, 생략한 범위가 있으면 화면에 표시한다.
- 취소·필터·대사 이동은 조회일 뿐 선택을 다시 실행하거나 과거 게임 상태를 복원하지 않는다.

## 완료 기준

- [ ] 이동 취소·선택 취소·편성 변경을 방문·확정 선택·합류로 잘못 기록하지 않는다.
- [ ] 같은 사건의 재전달·화면 재표시·중단 재개로 여정이 중복되지 않는다.
- [ ] 일반 저장 복원과 전투 재시작에서 정의한 기록 범위가 복원되며 미래 분기 정보가 남지 않는다.
- [ ] 미경험 사건·미선택 항목을 목록·검색·대사 연결 어느 곳에서도 노출하지 않는다.
- [ ] 대사 기록이 없어지거나 이전 저장에 없을 때 안전하게 안내하고 실제 선택·난수는 바뀌지 않는다.

## 작업 순서

1. 방문·선택·합류·주요 사건별 확정 시점과 근거를 목록화한다.
2. F4 사건과 연표 reducer, 중복·재시작 범위 검사를 구현한다.
3. F3 저장 및 여정 필터·상세 화면을 연결한다.
4. [28번](28.md)의 최근 선택과 [39번](39.md)의 보관 대사로 읽기 전용 연결을 추가한다.

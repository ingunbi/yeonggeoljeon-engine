# 09. 사용할 수 없는 책략의 이유 표시

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 작성일: 2026-11-09
- 우선순위: P1 · 단계: M1
- 선행조건: F2 규칙·사용 조건 조회. 예측 기능의 완료와 독립적으로 개발한다.
- 기준: [전체 목록](../../../BACKLOG.md), [공통 구조](../architecture.md), [검증 기준](../verification.md).

## 현행과 차이

- [OriginalBattleScreen.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattleScreen.swift)의 `strategyRows`는 MP·비 여부로 enabled만 만든다.
- [OriginalBattleView.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattleView.swift)의 `openStrategies`는 이름·비용·enabled를 전달한다.
- [CanvasOverlay.swift](../../../Sources/YeonggeoljeonEngine/CanvasOverlay.swift)의 `CanvasMenu.Option.help`는 있지만 비활성 행에는 현재 사유가 없다.
- 키보드와 마우스 탐색은 비활성 행을 건너뛴다. 추가 기능은 선택하지 못하는 행에서도 이유를 읽게 한다.

## 목적과 화면 흐름

1. 책략 목록을 열면 소모 MP와 현재 사용 불가 사유를 행에 바로 표시한다.
2. ‘MP 3 부족’, ‘비 때문에 사용 불가’처럼 현재 상태를 구체적으로 쓴다.
3. 읽기 전용 상세에서 여러 사유와 습득표의 일반 조건을 확인한다.
4. 비활성 행을 읽는 동작과 실제 실행 선택을 분리한다.
5. 활성 책략의 기존 대상 선택·취소 흐름을 유지한다.

## 구현 범위와 진입점

- 신규 타입 제안 `StrategyAvailability`는 ability ID, 필요/현재 MP, 이유 코드 목록과 실행 가능 여부를 가진다.
- 표의 레벨 조건, 병과 제한, 상태·행동 완료, 날씨 조건을 F2에서 조회한다.
- [OriginalStrategyOperation.swift](../../../Sources/YeonggeoljeonEngine/OriginalStrategyOperation.swift)의 `begin`과 같은 규칙 생산 지점을 공유한다.
- 영문 오류 문자열을 파싱해 상태를 추론하지 않고 안정적인 이유 코드를 한국어 문구로 매핑한다.
- 선택 목록 수준의 불가와 특정 대상의 사거리·지형·회복 불가를 구분한다.
- 아직 대상을 선택하지 않은 상태에서 특정 대상이 없다고 모든 책략을 일괄 비활성화하지 않는다.
- 사유가 둘 이상이면 행에는 주요 사유, 상세에는 전체 사유를 고정 순서로 표시한다.
- `CanvasMenu`의 입력 차단 규칙은 유지하며 별도 읽기 상세 진입 또는 행 설명으로 접근성을 제공한다.
- [StrategyGuideDetails.swift](../../../Sources/YeonggeoljeonEngine/StrategyGuideDetails.swift)의 일반 조건 설명과 연결한다.
- 공개된 대상만 다루며 숨겨진 적의 점유·존재를 사유 문구에 포함하지 않는다.

## 저장과 예외

- 사용 가능 여부와 사유는 현재 상태에서 계산하므로 저장하지 않는다.
- 이전 세이브·설정의 스키마 변경 없이 시작할 수 있는 UI 기능이다.
- 날씨·MP·병과·레벨·상태가 바뀌면 열려 있는 표시도 갱신한다.
- 읽기 상세를 열어도 MP·행동 플래그·로그·RNG가 바뀌지 않는다.
- 표 누락은 ‘데이터 확인 불가’로 표시하고 정상적인 사용 불가 사유로 위장하지 않는다.
- 실제 실행 시에는 기존 실행기가 다시 검사하며 상세 조회가 실행 권한이 되지 않는다.

## 완료 기준

- [ ] MP 부족 수량, 비와 화계, 복합 사유가 현재 상태와 일치한다.
- [ ] 비활성 행을 클릭·키보드로 읽어도 실행되거나 비용이 소모되지 않는다.
- [ ] 대상 수준의 지형·사거리 거부와 시전자 수준의 불가를 구분한다.
- [ ] 날씨·MP·전직 후 이전 불가 사유가 남지 않는다.
- [ ] 조회 전후 상태·RNG 불변과 기존 책략 실행 경로의 재검사를 확인한다.
- [ ] 실제 창에서 긴 사유·키보드 탐색·습득표 왕복을 읽을 수 있다.

## 작업 순서

1. 실행기와 UI가 공유할 이유 코드·우선순위를 F2로 정리한다.
2. 책략 행에 비용·사유를 연결하고 읽기와 실행 입력을 분리한다.
3. 상세 안내·습득표 이동·상태 변경 갱신을 추가한다.
4. 합성 조건 조합과 실제 창 입력을 별도로 검증한다.

이 문서는 구현 계획이다. 기능 구현이나 테스트 통과를 의미하지 않는다.

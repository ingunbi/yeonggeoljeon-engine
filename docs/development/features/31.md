# 31. 전투 다시 보기

- 작성일: 2026-11-09
- 상태: 부분 구현 · 안정화 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P3 · 단계: M5
- 선행: 공통 F4 확정 이벤트·F3 저장 버전 정책, [08번](08.md)의 대상 전투 결정적 검증. 대규모 별도 과제다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [BattleResultLog.swift](../../../Sources/YeonggeoljeonEngine/BattleResultLog.swift)는 확정 결과 500건의 조회용 기록이며 명령이나 모든 난수 상태를 재실행하는 기록이 아니다.
- [OriginalPlayVerification.swift](../../../Sources/YeonggeoljeonEngine/OriginalPlayVerification.swift)의 `OriginalPlayInput`, `verifyOriginalPlay`는 고정 단계로 입력을 재생하고 최종 상태·난수를 보고한다.
- [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `battleStartSnapshot`은 소개가 끝난 첫 턴 직전의 복원 경계를 제공한다.
- 추가 범위는 플레이 중 재생 자료 수집, 호환 확인, 분리된 뷰어와 턴 탐색이다. 기존 상세 로그를 리플레이라고 부르지 않는다.

## 목적과 화면 흐름

1. 기록을 켜고 끝낸 전투는 `전투 다시 보기` 목록에 전투명·턴·결과·호환 상태가 나타난다.
2. 항목을 열면 별도 재생 화면에서 재생·정지·배속·턴 이동을 사용한다.
3. 원하는 턴에서 부대와 확정 행동 기록을 조회하되 실제 이동·공격 명령은 내리지 못한다.
4. 재생을 닫으면 본편의 원래 화면과 입력 경계로 돌아간다.
5. 자료나 엔진 버전이 맞지 않으면 필요한 조건을 안내하고 잘못된 결과를 재생하지 않는다.

## 구현 설계와 데이터

- 새 제안 타입 `BattleReplayManifest`에 기록 버전, 엔진 규칙 식별자, 자료 해시, battle/attempt ID, 별도 recording/branch ID, 시작·종료 상태 해시를 둔다.
- 새 제안 타입 `BattleReplayInput`은 수락된 플레이 명령과 선택만 기록하고 불법 입력·미리보기·메뉴 조회를 제외한다.
- 시작 상태는 첫 턴 이전의 검증 가능한 경계, 런타임 동적 값, RNG와 캠페인 이벤트 문맥을 포함한다.
- 원본 지도·그림·음악·대사·정적 수치표를 리플레이에 복제하지 않는다. 필요한 자료는 호출자가 지정한 로컬 자료에서 해시로 연결한다.
- F4 사건은 결과 확인·탐색 색인에 사용한다. 결과 사건을 명령처럼 다시 적용하여 피해를 이중 반영하지 않는다.
- `OriginalPlayInput`의 현재 지원 범위를 재사용하되 누락된 합법 입력은 명시적으로 추가하고 버전으로 구분한다.
- 재생 호스트·인물 상태·RNG는 본편에서 완전히 분리된 소유권을 가진다. 공유하는 것은 불변 자료뿐이다.
- 처음에는 시작 경계부터 목표 턴까지 재생한다. 임의 연출 중 스냅샷으로 바로 건너뛰는 기능은 제외한다.
- 속도는 표현만 바꾸고 고정 시뮬레이션 단계·RNG 호출 순서는 유지한다.
- 중간·최종 상태 해시가 기대값과 다르면 즉시 정지하고 최초 불일치 입력을 표시한다.

## 저장·호환·오류·취소

- 리플레이는 본편 저장과 별도 경로·형식에 보관하고 본편 자동 저장 함수를 호출하지 않는다.
- 본편 F3에는 기록 중인 시도의 식별·커서만 필요 범위로 보존하여 중단 재개 뒤 입력이 빠지거나 중복되지 않게 한다.
- 지원하는 초기 상태·입력·규칙 버전 조합을 명시한다. 미래 버전은 읽기 실패로 처리하고 덮어쓰지 않는다.
- 기록 용량 상한과 보존 설정을 제공한다. 공간 부족 시 본편 플레이는 유지하고 해당 리플레이를 미완성으로 표시한다.
- 도중에 기록을 끈 전투와 일부 입력이 누락된 파일을 완전 재생 가능 항목으로 표시하지 않는다.
- 저장 후 이어하기는 저장된 전투 attempt ID를 유지한다. 기록 끝의 커서에서 정상 재개하면 같은 리플레이에 이어 기록한다. 과거 커서에서 다른 입력을 시작할 때만 새 recording/branch ID를 발급하고 공통 입력 구간을 참조한다. 전투 시도 ID를 바꾸거나 서로 다른 분기의 뒷부분을 이어 붙이지 않는다.
- 로컬 자료 의존 기록은 공개 배포 파일로 자동 내보내지 않는다. 내보내기 범위 감사는 별도 완료 조건으로 둔다.

## 완료 기준

- [ ] 시작 상태와 입력으로 재생한 중간·최종 게임 상태 및 RNG가 원래 전투와 일치한다.
- [ ] 배속·턴 탐색·조회·재생 취소가 본편 상태·저장 파일·원본 자료를 변경하지 않는다.
- [ ] 중단 재개로 이어 수집한 기록에도 입력·확정 사건 중복 또는 누락이 없다.
- [ ] 과거 저장에서 갈라진 기록은 별도 branch ID를 가지며, 본편 attempt ID·전적·메모를 새 전투 시도처럼 초기화하지 않는다.
- [ ] 자료 해시·규칙 버전·입력 버전 불일치와 손상·미완성 기록을 명확히 거부한다.
- [ ] 아카이브에 원본 정적 자료가 포함되지 않으며 합성 기록만 공개 테스트에 사용한다.
- [ ] 실제 창 재생 조작과 결정적 상태 검증 결과를 별도로 기록한다.

## 작업 순서

1. 입력·시작 상태·버전 명세와 기록 크기 한도를 합성 전투로 확정한다.
2. 수집기와 독립 재생 호스트를 구현하고 원래 실행과 상태·RNG를 대조한다.
3. 턴 색인·재생 UI·중단 재개 수집을 연결한다.
4. 대상 전투 검증을 넓힌 뒤 호환 범위를 공개한다. 전체 전투 지원을 먼저 선언하지 않는다.

# 30 상황별 초보 안내

- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P2
- 개발 단계: M3
- 선행조건: 09 사용 불가 이유, 26 상태 설명, F4 확정 사건
- 기준일: 2026-11-09

## 목적과 현재 구현

처음 마주친 규칙을 필요한 순간에 짧게 설명한다. 현재 [main.swift](../../../Sources/YeonggeoljeonEngine/main.swift)의 `showPlayGuide`는 정적인 조작표다. [OriginalBattleView.swift](../../../Sources/YeonggeoljeonEngine/OriginalBattleView.swift)의 상태·명령 변화에 안내 진입점을 추가한다.

## 사용 흐름과 화면

1. 새 사용자에게 상황 안내 사용 여부를 설정에서 제공하며 기본값은 켬이다.
2. 첫 범위 책략·첫 혼란·이동 후 취소 가능 상태 등 정해진 상황에 짧은 안내를 띄운다.
3. ‘알겠습니다 / 다시 보지 않기 / 자세히’를 제공한다.
4. 자세히는 기존 책략·상태 설명·조작표로 연결한다.
5. 도움말에서 본 안내와 끈 안내를 다시 열 수 있다.

## 구현 범위와 데이터

- 제안 타입 `TutorialTopic`은 안정적인 주제 ID, 발생 조건, 짧은 설명, 연결 대상, 중복 억제 상태를 가진다.
- 안내는 확정 사건 또는 현재 입력 단계에서만 발생한다. 다음 적 행동이나 숨겨진 이벤트를 예고하지 않는다.
- 한 번에 한 안내만 표시하며 기존 대사·선택창 위에 겹치지 않는다.
- 상태가 지나가면 잘못된 위치를 가리키는 안내를 폐기하고 도움말에서 확인할 수 있게 한다.
- 실제 동작을 자동 실행하거나 전투의 정답을 강제하지 않는다.
- 09·26번과 규칙 설명을 공유해 별도의 모순된 문구를 만들지 않는다.

## 저장과 호환

본 주제와 끈 주제는 사용자 설정에 주제 ID로 저장한다. 게임의 원본 플래그로 사용하지 않는다. ‘안내 다시 보기’는 기록을 초기화할 수 있다. 새 주제는 별도 ID로 추가한다.

## 예외와 취소

건너뛰기·적 턴·일기토 중에는 안내를 예약하되 안전한 명령 경계에서 유효성을 다시 검사한다. 중단 저장 확인창과 충돌하면 안내가 양보한다. 키 재설정 후 안내 문구는 실제 바인딩을 읽는다.

## 완료 기준

- [ ] 동일 주제는 설정된 반복 규칙 이상으로 나타나지 않는다.
- [ ] 이미 끝난 상황에 오래된 안내가 뜨지 않는다.
- [ ] 안내를 닫거나 끄는 행위가 공격·턴 종료로 전달되지 않는다.
- [ ] 안내 사용 여부에 따른 게임 상태와 난수 결과가 같다.
- [ ] 도움말에서 꺼진 주제를 다시 열고 전체 초기화할 수 있다.

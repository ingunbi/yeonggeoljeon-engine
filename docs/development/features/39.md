# 39. 대사 기록 검색과 북마크

- 작성일: 2026-11-09
- 상태: 구현 · 검증 중 ([현재 구현 범위와 남은 검증](../implementation-status.md))
- 우선순위: P3 · 단계: M4
- 선행: F3 진행 종속 기록 저장. [29번](29.md)의 장면 참조와 [34번](34.md)의 표시 시간 보존을 공유한다.
- 공통 기준: [구조와 데이터](../architecture.md), [검증 계획](../verification.md)

## 현행과 차이

- [OriginalCampaignView.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignView.swift)의 `dialogueLog`는 `(speaker,text)` 배열로 뷰가 소유한다.
- `presentDialogue`에서 실제 표시한 대사를 추가하며 300건을 넘으면 앞 항목을 제거한다. 이 현행 한도를 확장 설계의 출발점으로 삼는다.
- `presentLog`는 전체 기록을 목록으로 보여주고 조회를 닫으면 기존 대사로 돌아온다. 검색·북마크·저장된 대사 이력은 없다.
- [OriginalCampaignHost.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignHost.swift)의 `OriginalCampaignResume`에는 이 뷰 배열이 들어 있지 않다.
- 추가 범위는 경험한 대사를 찾고 보관하는 기능이다. 과거 선택 변경이나 장면 되감기 기능은 아니다.

## 목적과 화면 흐름

1. 기존 `대사 기록` 상단에 검색어·인물·장면 필터와 `북마크만`을 제공한다.
2. 결과 목록은 실제 표시 순서를 유지하고 선택 시 전체 문장과 인물·장면 정보를 보여준다.
3. 별표 또는 키보드 버튼으로 북마크를 설정·해제한다.
4. [29번](29.md) 여정 항목에서 연결된 대사로 이동할 수 있다.
5. 검색을 닫으면 읽던 대사와 남은 자동 넘김 시간·입력 초점으로 돌아간다.

## 구현 설계와 데이터

- 새 제안 타입 `DialogueHistoryEntry`에 안정 ID, 표시 순번, speaker ID·표시명, 본문, 확인 가능한 장면 식별자와 북마크 여부를 둔다.
- 기록 생성은 `presentDialogue`의 실제 표시 경계에서 수행한다. 원본 대사 목록을 미리 읽어 검색 색인을 만들지 않는다.
- 본문이 같은 반복 대사도 별도 표시 사건이면 기록한다. 같은 뷰 갱신의 재전달만 안정 ID로 중복 제거한다.
- 스킵 중 문장 전체가 실제로 제시된 대사는 포함하되 화면에 도달하지 않은 명령의 대사는 포함하지 않는다.
- 검색은 유니코드 정규화를 적용한 부분 문자열과 인물 ID 필터를 사용하며 원문은 바꾸지 않는다.
- 장면 필터는 기록할 때 확인한 장·지도·레코드 문맥을 사용하고 미확인 장면에 이름을 지어 붙이지 않는다.
- 기본 최근 기록은 기존 300건을 유지하고 북마크 기록은 별도 최대 200건을 제안한다.
- 북마크가 최근 목록에서 밀려나도 한 사본으로 보존한다. 중복 저장이 아니라 ID 참조로 두 목록을 구성한다.
- 북마크 상한 도달 시 기존 항목을 지우거나 보관 범위를 선택하게 하고 자동으로 중요한 기록을 삭제하지 않는다.
- 새 제안 `DialogueHistoryStore`는 캠페인별 진행 기록을 소유하며 AppKit 검색 입력과 분리한다.

## 저장·호환·오류·취소

- 대사 이력·북마크는 F3에 게임 진행과 함께 원자적으로 저장한다. 독립 전역 기록 파일로 미래 대사가 유입되게 하지 않는다.
- 일반·중단 저장 복원 시 해당 시점의 기록으로 돌아간다. 새 게임은 새 기록을 시작한다.
- 예전 저장과 원작 저장에는 `이 저장 이전의 대사 기록 없음`을 표시하고 원문에서 과거 내용을 재구성하지 않는다.
- 총 글자 수·항목 수·ID 유일성과 유효 문자열을 검증하여 과도한 기록으로 저장 크기 제한을 넘지 않게 한다.
- 보관 한도를 벗어난 기록과 끊어진 여정 참조는 `보관된 대사 없음`으로 처리하고 미래 원문을 대신 열지 않는다.
- 검색 결과 없음·입력 취소·북마크 해제는 게임 선택·난수·원본 자료를 변경하지 않는다.
- 대사 본문을 담은 실제 저장·보고서는 무시되는 로컬 경로에만 두며 공개 테스트는 합성 문장만 사용한다.

## 완료 기준

- [ ] 실제 표시된 대사만 인물·단어·장면으로 검색되며 미표시·미경험 문장은 노출되지 않는다.
- [ ] 같은 문장의 별도 표시와 동일 표시의 재그리기를 구분하여 누락·중복이 없다.
- [ ] 최근 300건을 넘겨도 북마크가 보존되고 북마크 200건 상한에 명확한 안내가 나온다.
- [ ] 일반·중단·과거 저장 복원에서 기록 범위가 맞고 예전 저장의 기록 부재를 안전하게 처리한다.
- [ ] 검색을 닫으면 대사·남은 표시 시간·입력 초점이 보존되며 과거 선택을 실행하지 않는다.

## 작업 순서

1. 표시 사건 ID와 300건·북마크 보관 정책을 합성 대사로 검사한다.
2. 뷰 배열을 진행 종속 기록 모델에 연결하고 F3 호환 저장을 구현한다.
3. 검색·필터·북마크 UI와 [29번](29.md) 장면 참조를 연결한다.
4. 대사 스킵·중단 재개·한도 초과·과거 저장 복원·조회 취소를 확인한다.

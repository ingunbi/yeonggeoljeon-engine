# 08. 새 게임부터 엔딩까지 연속 플레이 검증

- 작성일: 2026-11-09
- 상태: 검증 계획 완료 · 실행 대기
- 우선순위: P0 · 단계: M0~M5 지속 검증
- 선행: 현재 공개 재생기 사용 가능. [07번](07.md)·[12번](12.md) 및 이후 기능 완료 때 해당 경로를 추가한다.
- 공통 기준: [검증 계획](../verification.md), [구조와 데이터](../architecture.md)

## 현재 확인된 범위와 남은 범위

- [README](../../../README.md)의 소스 검사와 로컬 진단 절에는 정상 수치·합법 입력으로 초반 여섯 전투를 지나 다음 전투 진입까지 확인한 범위가 명시되어 있다.
- 같은 절의 후반 검사는 지정한 원작 저장에서 서릉 승리 후 양양 진입까지의 단편이며, 양양 전투 행동은 포함하지 않는다.
- 턴 제한 패배·재시작 선택과 엔딩 직전 상태에서의 엔딩 진입은 별도 경로다. 새 게임부터의 연속 완주 증거로 합치지 않는다.
- 이 문서는 계획만 작성한 것으로, 정상 수치의 전체 캠페인 완주나 실제 OS 입력 검증을 새로 수행했다는 뜻이 아니다.
- [OriginalPlayVerification.swift](../../../Sources/YeonggeoljeonEngine/OriginalPlayVerification.swift)의 `OriginalPlayInput`, `verifyOriginalPlay`는 합법 입력을 기존 호스트·전투 흐름에 전달한다.
- [OriginalCampaignVerification.swift](../../../Sources/YeonggeoljeonEngine/OriginalCampaignVerification.swift)의 `verifyOriginalCampaignHost`는 선택·전투 경계에서 멈추며 완주 검사와 다르다.

## 검증 목적과 경로 구성

1. 새 게임에서 정상적으로 도달 가능한 한 경로를 먼저 엔딩까지 이어가고, 주요 분기를 추가한다.
2. 구간별 진입 상태·입력·종료 상태를 연결해 앞 구간의 실제 결과가 다음 구간의 시작임을 증명한다.
3. 연속 전투, 보존 부대 배치, 구매·회복, 퇴각·패배, 일반·중단 저장 재개를 경로 표에 포함한다.
4. 실제 창에서는 대사 건너뛰기, 마지막 소개 대사, 승리조건, 선택과 입력 초점을 별도 확인한다.
5. 실패 시 최초 불일치 입력과 지원하지 않는 명령 경계를 남기고, 해당 경로를 미완료로 유지한다.

## 구체적 실행 설계

- 입력 재생은 `OriginalPlayInput.validate`와 `performBattle`를 통과하게 하고 승리·좌표·능력치·플래그를 강제로 주입하지 않는다.
- 출발 seed, 고정 시간 간격, 엔진 소스 식별자, 입력 해시와 자료 식별 해시를 실행 명세에 기록한다.
- 새 제안 타입 `CampaignRouteManifest`로 경로 ID, 분기, 구간 연결, 기대 경계, 증거 종류를 관리한다.
- 공개 명세에는 합성 ID만 사용한다. 실제 대사·지도·입력 보고서는 무시되는 로컬 출력에 둔다.
- 비교 기준은 게임 상태·난수·확정 기록이며 재구성되는 화면 커서는 별도로 명시한다.
- 저장 전후 같은 남은 입력을 적용하여 중단하지 않은 기준 경로와 비교한다.
- 연속 전투는 단순 다음 지도 진입뿐 아니라 보존 슬롯·병력·소모품·누적 수치를 확인한다.
- 정상 패배, 총퇴각 제한, 재시작 선택은 각각 결과·재개 위치·난수 규칙을 검사한다.
- 미지원 opcode는 정확한 레코드·원본 바이트 오프셋과 함께 실패로 남기며 통과 처리하지 않는다.
- 실제 창 검증은 프레임 캡처만으로 대체하지 않고 키보드·마우스 입력 전달과 화면 반응을 함께 기록한다.

## 자료·저장·오류 보호

- 원본 실행 파일은 실행하거나 수정하지 않는다. 자료 선택과 추출은 기존 도구 경계를 지킨다.
- 실물 검사는 호출자가 고른 원본 디렉터리가 있을 때만 실행하며 원본 파일 해시를 전후 비교한다.
- 기존 사용자 세이브를 덮어쓰지 않고 격리된 저장·출력 경로를 사용한다.
- 공개 테스트는 합성 입력만 포함하고 실물 자료가 없으면 `건너뜀`으로 기록한다.
- 작업량 상한·미지원 명령·불법 입력·검증 불일치는 원인을 구분하고 마지막 정상 경계를 보존한다.
- 실행 중단 뒤 이어 검증할 때 출발 저장의 해시와 이전 구간 연결을 다시 검사한다.
- 사람이 플레이한 검증, 자동 정상 입력, 강화한 수치를 이용한 탐색, 정적 분석, 원작 런타임 비교를 서로 대체하지 않는다.

## 완료 기준

- [ ] 정상 수치의 새 게임 출발부터 엔딩 종료까지 한 경로가 연결되고 입력·상태·난수 증거가 남는다.
- [ ] 주요 분기와 미검증 분기 목록을 함께 공개하여 단일 완주를 전체 경로 검증으로 표현하지 않는다.
- [ ] 연속 전투·패배·재시작·일반 저장·중단 저장 각각의 재개 결과가 기준 경로와 일치한다.
- [ ] 실제 창에서 초반 대사 건너뛰기와 후반 전환·입력 초점을 확인한 결과가 자동 검증과 별도로 남는다.
- [ ] 원본 해시 불변과 사용자 세이브 보존을 확인하고, 실물 미실행 검사를 통과 수에 넣지 않는다.
- [ ] M1~M5의 기능 추가 후 영향 경로를 재검증하며 새 오류가 있으면 해당 완료 판정을 되돌린다.

## 작업 순서

1. 기존 증거 범위를 경로 표로 옮기고 정상 입력으로 아직 이어지지 않은 구간을 식별한다.
2. 초반 여섯 전투 이후를 연결하고 후반 단편과 별개로 새 게임 출발 엔딩 경로를 완성한다.
3. 분기·연속 전투·저장과 재시작 변형을 실행하고 최초 불일치를 수정 대상으로 분류한다.
4. 실제 창 검증을 수행하고 결과·한계·미검증 경로를 갱신한다.
5. 이후 단계별 변경에서 해당 경로를 다시 실행한다. 이 문서 작성 자체는 검증 실행이 아니다.

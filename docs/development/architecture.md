# 플레이 보조 기능 공통 설계

상태: 설계 완료 · 구현 대기. 기준일: 2026년 11월 9일. [우선순위와 기능 목록](README.md)의 42개 작업이 공유할 계약을 정의한다. 아래 F1~F6과 새 데이터 타입 이름은 제안 설계이며 현행 구현의 존재를 뜻하지 않는다. 필요한 계약부터 작게 구현하고, 전체 공통 계층을 먼저 완성하느라 화면 개선을 미루지 않는다.

## F1 상태를 바꾸지 않는 미리보기

대상: 01·02·03·04·05·11·14·17·18·25·35번.

입력은 값으로 복사한 인물·부대·지형·날씨·행동 상태와 필요한 규칙 표다. 제안 타입 `BattleProjectionInput`에는 상태 세대 번호와 공개 가능한 정보 집합을 포함한다. `OriginalPeople`이나 캠페인 호스트의 변경 가능한 참조를 계산 작업에 넘기지 않는다.

출력은 표시 가능한 대상, 필요한 경로, 효과, 불가 이유, 불확실성을 가진 구조화된 값이다. 임의 문자열을 다시 해석해 합산하지 않는다. 피해 설명·격파 여부·예상 경험치는 같은 계산 결과에서 만든다.

1. 현재 수동 입력 경계에서 필요한 상태를 캡처한다.
2. 이동을 가정할 때는 복사본의 위치·점유 상태를 바꿔 계산한다. 실제 이동·취소 API를 호출하지 않는다.
3. 확정 수치, 확률, 조건부 결과, 알 수 없는 부분을 구분한다. 라이브 RNG의 다음 값을 읽어 성공 여부를 미리 공개하지 않는다.
4. 퇴각·일기토·증원처럼 스크립트가 개입할 경계 이후는 근거 없이 계속 시뮬레이션하지 않는다. 해당 이후의 예측 범위를 제한한다.
5. 결과를 그리기 전에 상태 세대와 선택 대상이 일치하는지 확인한다. 다른 턴·장수·지도에서 온 오래된 결과는 버린다.

미리보기는 게임 상태, RNG, 소지품, 경험치, 이벤트 기록, 실제 행동 완료 플래그에 영향을 주지 않는다. 반복 조회·취소·설정 변경 전후 동일성을 합성 입력으로 검증한다.

초기 구현은 작은 계산을 동기적으로 처리할 수 있다. 큰 위협 지도와 협공 탐색은 불변 입력을 사용해 분할하거나 작업 큐에서 계산한다. 지도·인물·날씨·상태·장비 중 하나라도 바뀌면 관련 캐시를 무효화한다. 캐시 키를 좌표와 병과만으로 제한하지 않는다.

단순 커서 예측은 초기 성능 목표로 95백분위 50ms 이내를 둔다. 이는 측정 전 목표이며 개발 장비·지도 크기·부대 수를 기록해 검증한다. 협공에는 별도 탐색 상한을 두며, 예산을 넘으면 최적해라고 주장하지 않고 현재 후보와 제한을 표시한다.

## F2 사용 가능 조건과 규칙 설명

대상: 09·15·16·17·23·25·26·27·30·38번과 F1.

제안 타입 `ActionAvailability`는 가능 여부, 구조화된 이유, 필요한 수치, 공개 가능한 설명을 돌려준다. MP·날씨·사거리·지형·혼란·이미 행동함 등의 판정은 기존 규칙 함수에서 추출하거나 공통화한다. UI에서 비슷한 조건식을 새로 작성해 실행과 어긋나게 하지 않는다.

- 판정 단계에서 상태나 RNG를 변경하지 않는다. 실제 실행 직전 기존 명령 진입점에서 다시 검사한다.
- 조건이 여러 개일 때 직접 해결할 수 있는 이유를 먼저 보여주고 상세 보기에서 나머지를 설명한다.
- 비활성 행도 이유를 읽을 수 있게 한다. 키보드 탐색에서 건너뛰는 행에만 도움말을 묶지 않는다.
- 숨겨진 적·미등장 장수·미확인 사건 조건을 불가 이유에 포함하지 않는다.
- 미지원 규칙은 ‘현재 확인할 수 없음’으로 구분한다. 임의의 이동·전투 결과를 만들어 주지 않는다.
- 회복이 확률인 상태에는 남은 턴을 꾸며 표시하지 않는다. 상성과 정수 계산은 실제 수식의 순서를 보존한다.

목표와 이벤트 힌트는 UI의 문자열 분석으로 판정하지 않는다. 해독 자료와 현재 캠페인 상태를 연결한 확인된 목표 사실을 따로 제공한다. 23번은 공개된 현재 목표, 06번은 사용자가 켠 힌트 수준에 따른 확인된 추가 조건을 담당한다.

## F3 저장 소유권과 호환

대상: 07·10·12·19·28·29·31·32·36·37·38·39·41번과 설정 기능.

| 데이터 | 저장 소유자 | 복원 동작 |
|---|---|---|
| 병력·소지품·RNG·진행 커서 | 기존 캠페인 스냅샷 | 원래의 상태로 복원 |
| 전적·여정·선택·상점 관측 | 제안 `CampaignExtras` | 같은 스냅샷 시점으로 복원하여 미래 정보를 역유입하지 않음 |
| 지도 메모·보호 물품·편성 프리셋·장수 즐겨찾기 | 캠페인 확장 정보 | 인물 ID·물품 ID·전투 시도 ID 기준으로 검증 후 복원 |
| 키 배치·글자 크기·색상·일시정지 설정 | 앱 설정 | 게임을 불러와도 사용자의 현재 설정 유지 |
| 계산 캐시·호버·검색 임시 결과 | 저장하지 않음 | 새 상태로 다시 계산 |
| 리플레이·연습 상태 | 일반·중단 저장과 분리된 로컬 저장소 | 재생·연습 전용 문맥에서만 읽음 |

게임 스냅샷과 그에 종속된 확장 정보는 동일한 원자적 저장 단위로 커밋한다. 서로 독립된 파일 두 개가 모두 갱신되리라고 가정하지 않는다. 메타데이터와 본문 교체의 구체적인 순서·크기 제한·마이그레이션은 [12번](features/12.md)에서 정의한다.

현재 기본 복원 형식은 `OriginalCampaignResume.format == 1`이다. 새 스키마의 버전과 마이그레이션 함수를 명시하고, 과거 저장은 확장 정보가 없는 상태에서 읽는다. 잘못된 게임 상태는 명시적으로 거부하고, 선택적인 편의 정보가 손상된 경우의 복구 범위는 표시한다. 새 데이터를 이해하지 못하는 구형 빌드가 저장을 덮어쓰며 확장 정보를 조용히 잃게 하는 방식은 허용하지 않는다.

기존 저장은 읽기만으로 변환하거나 덮어쓰지 않는다. 다음 명시적 저장에서 새 형식으로 쓸 때 원본 보존·실패 복구를 제공한다. 원작 MSAVE·ESAVE와 이전 공개 엔진 포크의 파일을 새 저장 형식으로 취급하지 않는다. 원작 저장 가져오기는 계속 읽기 전용이다.

중단 저장은 별도 한 칸이다. 준비된 복원 상태가 유효하고 소모까지 성공한 뒤 화면을 교체한다. 일반 슬롯 백업·복구에 소모된 중단 파일을 포함하지 않는다. 중단 저장 예약 중 종료·취소·일시정지가 충돌하면 기존 게임을 유지하고, 완료되지 않은 저장을 성공으로 표시하지 않는다.

캠페인 실행과 전투 시도를 구별하는 식별자를 제안한다. 패배 후 재시작은 새 전투 시도, 저장 후 이어하기는 같은 시도로 처리한다. 생성에 게임 RNG를 사용하지 않으며, 시간·UUID 같은 메타데이터는 전투 결정성 비교 대상과 구분한다.

과거 저장에서 입력이 갈라지는 리플레이는 전투 시도 ID와 별개의 기록·분기 ID로 구분한다. 기록 분기 때문에 캠페인의 전투 시도나 전적·메모를 초기화하지 않는다. 일반 재개는 저장된 기록 커서에서 이어가고, 다른 분기의 입력은 같은 기록 뒤에 붙이지 않는다.

## F4 확정 사건과 기록

대상: 10·24·28·29·31번. 표시 속도나 애니메이션 완료 콜백이 기록을 소유하지 않는다.

제안 `CommittedGameEvent`에는 캠페인 실행 ID, 전투 시도 ID, 단조 증가 순번, 턴·진영, 행위자·대상 ID, 사건 종류, 확정 수치, 사건 출처를 넣는다. 원본 자료를 참조하는 오프셋과 식별자는 로컬 기록에 유지하되, 원본 대사와 자료를 공개 소스의 고정 문자열로 옮기지 않는다.

- 공격·반격·책략·물품은 효과가 실제로 커밋된 경계에서 기록한다. 실패·거절과 미리보기는 성공 사건으로 기록하지 않는다.
- 스크립트가 직접 바꾸는 병력·상태·증원은 별도 사건으로 식별한다. 기존 행동 기록과 중복 집계하지 않는다.
- 불분명한 변화의 원인을 특정 공격자에게 돌리지 않는다. 확정된 변화량만 표시하고 출처가 사건 처리임을 구분한다.
- 전투 결과는 한 시도당 한 번 집계한다. 로드·재시작·연속 전투에서 중복 승리나 보상을 만들지 않는다.
- 로그 한도와 누락 건수를 보관한다. 기록이 잘렸을 때 전투 전체 합계를 잘린 로그만으로 다시 계산하지 않는다.
- 저장 복원은 사건을 다시 발행하는 대신 저장한 순번과 집계 상태를 복원한다.

24번은 한 적 턴의 변화를 요약하고, 10번은 전투 전체 결과를 보관하며, 29번은 경험한 캠페인 사건을 관리한다. 28번은 이 사실과 현재 상태에서 짧은 재개 화면을 만든다. 각 화면이 같은 사실을 별도로 수집하지 않는다.

리플레이는 확정 사건만으로 실행하지 않는다. [31번](features/31.md)은 초기 상태·실제 입력·난수·자료 버전을 추가로 보관해 동일 규칙을 재생한다. 독립 전투 연구 모드를 정상 캠페인 재생으로 대체하지 않는다.

## F5 화면 입력과 일시정지

대상: 모든 새 화면, 특히 07·20·21·22·30·34·38·40번.

새 메뉴는 기존 Canvas 선택창과 게임 메뉴 경로로 연결한다. 메뉴 막대·게임 안 메뉴·단축키가 서로 다른 저장이나 행동 구현을 갖지 않도록 하나의 명령 경로를 사용한다. UI 객체 생성 도중 설정 알림이 재진입해 초기화 중인 싱글턴을 다시 요청하지 않도록, 초기 로드와 변경 알림을 구분한다.

입력은 상태별로 수동 전투, 대화, 선택창, 저장 확인, 연출, 일시정지 중 하나가 소유한다. 상위 모달이 닫힌 뒤 남은 클릭이나 키 반복이 하위 전투 행동으로 전달되지 않게 한다. Escape는 현재 선택창·명령의 취소를 담당하며 게임 종료와 혼동하지 않는다.

21번의 지도 배율과 22번의 글자·입력 설정은 다른 좌표 계층이다. 지도 좌표, 지도 카메라, 640×400 논리 캔버스, 창 좌표, Retina 픽셀 변환의 순서를 공유한다. 원작 화면 틀과 엔진 화면 모두에서 선택·호버·미니맵·범위가 같은 칸을 가리키는지 확인한다.

34번은 포커스 이탈과 최소화라는 일시정지 사유를 관리한다. 창 복귀가 사용자가 직접 건 일시정지를 해제하지 않는다. AppKit 메뉴·파일 선택창을 띄운 것과 다른 앱으로 전환한 것을 구분하고, 종료를 위해 기다리는 저장 경계가 자동 일시정지 때문에 영원히 도달하지 못하는 상황을 처리한다. 구체적 전이 규칙은 07·34번 문서에서 맞춘다.

표시는 기본적으로 기존 게임 규칙을 바꾸지 않는다. 길찾기·즐겨찾기·장바구니로 발행한 실제 행동도 현재 가능 여부를 다시 확인하며, 사용자가 확정하지 않은 공격·책략·대화 선택을 자동 실행하지 않는다.

원본 확대 전투 옵션과 엔진의 새 표시 정책은 분리한다. 현행 `OriginalCombat.physicalPrelude`는 일부 병과에서 원본 옵션워드에 따라 다른 횟수의 난수를 소비한다. 20번은 동일 원본 옵션워드를 유지한 채 화면 표현만 바꾸며, 기존 옵션값이 다른 두 경로의 난수가 같아야 한다고 요구하지 않는다.

## F6 확인된 정보와 검색

대상: 06·23·29·39·40·41·42번.

검색 입력은 호출자가 선택한 자료에서 생성된 읽기 전용 정보와 현재 플레이에서 확인한 사실이다. 실제 인물 ID와 표시용 목록 행, 전투 슬롯을 혼용하지 않는다. 이름이 같아도 ID로 구분하고, 검색 순서 변경이 게임의 부대 순서에 영향을 주지 않게 한다.

정보를 일반 규칙, 현재 공개 상태, 실제 경험한 사건, 사용자가 허용한 확인된 힌트로 분류한다. 검색 결과·검색 개수·자동 완성에도 같은 노출 규칙을 적용한다. 숨겨진 적이나 미경험 분기를 검색 결과의 빈칸·개수로 추측할 수 있게 하지 않는다.

39번은 이미 본 대사 기록을 검색하고, 41번은 마지막으로 확인한 상점 판매품을 기록한다. 기록이 없으면 없다고 표시하며, 자료에 존재한다는 이유로 방문 사실을 만들지 않는다. 관측 시점이 지난 상점 정보는 현재 재고로 단정하지 않는다.

원본에서 확인한 새 조건이 필요한 경우 Python 해독 출력을 확장하고 원본 위치·해시를 로컬에 남긴다. 공개 합성 데이터와 원본 자료를 분리한다. 원작 DOS 프로그램을 실행해 빈틈을 메우는 절차나 이전 공개 엔진 포크의 참조를 이 설계에 포함하지 않는다.

## 공통 완료 조건

1. 현재 저장과 원본 파일이 의도치 않게 바뀌지 않으며, 취소·오류가 현재 플레이를 보존한다.
2. 읽기 전용 조회를 넣은 실행과 넣지 않은 실행의 게임 상태·RNG가 같다.
3. 공개 가능한 정보만 표시하고, 예측·확률·확정 결과를 구분한다.
4. 새 데이터는 보관 상한·버전·기본값·복원 정책을 갖는다.
5. 실제 메뉴·키보드·마우스·포커스 전환을 포함하는 검증 결과가 [검증 기준](verification.md)에 맞게 기록된다.

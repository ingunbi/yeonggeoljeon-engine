# 관리·기록·재생 기능 수용 기준 감사

기준일: 2026-11-09. 대상은 13–15, 31–33, 35–42번이다. 문서의 완료 기준 순서대로 구현 경계와 확인 근거를 대응했다. **코드 연결, 합성 검사, 결정적 실제 자료 검사, 실제 창 입력은 서로 다른 증거**다. 이 문서만으로 전체 게임 완주나 원작 DOS 실행 결과와의 일치를 선언하지 않는다.

## 증거와 실행 범위

- 합성 데이터: [ManagementHelpersTests.swift](../../Sources/YeonggeoljeonEngine/ManagementHelpersTests.swift), [ReferenceHelpersTests.swift](../../Sources/YeonggeoljeonEngine/ReferenceHelpersTests.swift), [BattleArchiveTests.swift](../../Sources/YeonggeoljeonEngine/BattleArchiveTests.swift), [OriginalBattleScreenTests.swift](../../Sources/YeonggeoljeonEngine/OriginalBattleScreenTests.swift), [NativeSaveSlotsTests.swift](../../Sources/YeonggeoljeonEngine/NativeSaveSlotsTests.swift). 실제 원본 문장·지도·정적 자료를 테스트에 추가하지 않았다.
- 최신 관리 변경을 다시 복사한 scratch 빌드와 [집중 검사](../../build/development-20261109/archive-completion-check/focused-tests.log)가 exit 0으로 끝났다. archive 48개, native save 78개 및 관리·정보·overlay·전투 화면 합성 검사를 포함한다. 해당 복사본의 [소스 해시](../../build/development-20261109/archive-completion-check/focused-source-hashes.json)를 남겼다.
- 그 이전 전투 기록 전용 scratch 빌드는 성공했고 archive 합성 검사 **48개가 통과**했다. 해당 복사본의 전체 검사는 archive 이후 전투 보조의 `two distinct normal attacks ...` 검사에서 중단했다. 이 실패를 전체 통과로 계산하지 않으며 최신 전투 담당 변경과 통합 검사 결과는 별도로 확인한다.
- 이번 재검증은 [archive-completion-check/verification.json](../../build/development-20261109/archive-completion-check/verification.json)에 보관했다. 기존 6전투의 전투 입력 649개에 대해 완료 기록 동일 입력 재사용, JSON 커서 복원, 중간 seek 이후 완료, 참조 정확히 1개, 원래 아카이브 바이트 불변, 연습 승리·독립 재시작 및 본편 control 해시 불변을 확인했다(exit 0). `fixture-progress.json`과 `records/`는 별도 QA 메뉴에서 재현 가능한 로컬 fixture다.
- 기존 정상 입력 796개 경로는 7개 전투 진입·6개 전투 종료를 확인한 로컬 근거다. [기존 정상 기록/연습 검증](../../build/development-20261109/practice-play-verification/)과 [재생 안정화 검사](../../build/development-20261109/replay-stability-report.json)는 무시되는 로컬 파일이며 공개 테스트에 복사하지 않는다.
- 기존 실제 창 증거는 [stabilization-verification.json](../../build/development-20261109/stabilization-verification.json)이다. 사수관 재생 열기·2턴 이동·재생/정지·닫기, 준비 중 취소, 연습 별도 창 진입·저장하지 않고 본편 복귀가 기록되어 있다. **정리/복구 UI와 연습 완료 후 재시작·목록 복귀는 이 이전 증거에 포함되지 않는다.**
- 이번 담당 작업에서 사용자 저장이나 실제 게임 창을 조작하지 않았다. 파일 검사는 새 임시 디렉터리와 무시되는 개발 경로에서 수행한다.

이번 보완:

- 64개가 찼을 때 오래된 완료 참조를 조용히 탈락시키던 동작을 제거했다. 다음 기록은 정리 필요를 안내하며 본편 플레이는 계속한다.
- `기록 정리`에서 10/20/40/64개 보존 수를 정하고 후보를 확인한 뒤 이동한다. 자동 삭제하지 않는다.
- 기록 파일은 `archive-trash`에 **원본 바이트 그대로 이동**하고 SHA-256 복구 영수증을 남긴다. 영구 삭제는 없다. 디스크 사용량이 줄어든다고 안내하지 않는다.
- 진행 중 기록 정리, 복구 충돌, 변조, 심볼릭 링크, 참조 수 상한은 변경 전 거부한다. 여러 항목 정리 도중 실패하면 이미 성공한 항목만 보관 목록에 반영한다.
- 본편 F3의 `trashed` 참조로 복구 권한을 판단한다. 다른 저장의 파일을 복구해도 현재 저장에서 경험하지 않은 승리/연습을 해금하지 않는다. 미등록 기록의 전투명은 UI에서 읽어 노출하지 않는다.
- 같은 파일을 다른 저장에서 먼저 복구했을 때에는 현재 저장이 보관한 참조만 검증해 목록을 복원한다. 파일이 사라진 참조는 보관하지만 원본 자료에서 가짜 재생 기록을 생성하지 않는다.
- 보관함 내용은 공간을 차지한다. 활성 기록은 256 MB, 완료 참조는 64개, 보관 참조는 256개 상한을 둔다. 정리는 현재 앱 안에서 읽기/수정/이동이 겹치지 않도록 직렬화한다.

## 35 두 장수 비교

1. 수치 일치: 같은 `OfficerComparison.snapshot`/공유 능력 계산을 사용하며 실제 transfer 결과와 대조한 snapshot을 비교한다.
2. 기준 표시: 필드 사기 100, 전투 현재 사기, 레벨·장비를 표시한다. 카드 합성 생성 검사가 있다.
3. 현재 책략: 습득표 부재와 빈 목록을 구분하며 현재 병과/레벨을 이용한다.
4. 조회 불변: 각 탭 생성·좌우 데이터·원본 인물 인코딩 불변, 실제 격자 offset/이동 비용 이름 검사가 있다.
5. 오래된 대상 폐기: 진입마다 현재 companions/현재 전투 아군 ID를 재검사한다. **이탈/로드 및 좁은 창 실제 왕복은 추가 UI 관찰 대상**이다.

## 36 출전 프리셋

1. 강제 prefix/정원: 적용 계획 합성 검사 통과 근거가 있다.
2. 참가 불가/중복/초과/잘못된 ID: 별도 omission 이유를 검사한다.
3. 취소/실패 보존: 값 복사 계획·원본 selection 인코딩 불변; 저장 변경은 candidate validate 후 교체한다.
4. VM/지도/소지품 불변: 계획은 선택만 변경하고 Host가 최신 partySelection으로 재계산한다.
5. 저장 복원: 이름·순서·UUID roundtrip/이름 변경 검사가 있다. **자료 식별값을 추가했으며** 다른 자료·식별 없는 이전 프리셋은 자동 적용하지 않고 다시 저장하도록 안내한다. 이름 변경은 기존 식별값을 보존한다.

위 동작의 실제 편성 창 적용·취소·재개는 추가 관찰 대상이다.

1. 판매·필드/전투 폐기: `CampaignExtras.protects`의 같은 sell/discard 규칙을 사용하며 management 합성 검사에서 두 연산을 함께 확인한다. 실제 UI의 각 경로 거부 이유는 추가 관찰 대상이다.
2. 중복·슬롯 이동·전달: 장수 ID+물품 ID 규칙이며 전달 성공 시 받는 사람에게 보호를 합치고 주는 사람의 규칙을 보존한다. `transferProtection`과 중복 투영을 검사한다.
3. 기본 사용 가능/선택적 사용 보호: `.use`는 opt-in만 차단하며 기본 사용 허용과 사용 보호 전달 합성 검사가 있다. 실제 전투 도구 사용 확인은 별도다.
4. 스크립트 강제 소모: `.script`는 항상 보호를 우회하는 합성 검사. 특정 후반 원본 스크립트 경로 완료는 별도 정상 캠페인 검증 범위다.
5. 저장 시점 복원: extras roundtrip과 이전 저장 빈 기본값 검사. 전역 보호 상태 파일을 사용하지 않는다.

## 38 책략·도구 즐겨찾기

1. 순서/저장: 장수별 안정 action ID·순서·상한·중복 검증 및 F3 roundtrip; 새 캠페인은 빈 extras를 사용한다.
2. 전직/MP/물품 소진: 현재 병과/습득표/MP/날씨/소지품/상태 이유를 매번 계산한다. screen 합성 검사에서 MP 부족 비활성과 사유를 확인한다. 실제 전직 후 갱신 UI는 추가 관찰 대상이다.
3. 동일 도구/전달/재획득: 슬롯 대신 item ID를 조회하므로 현재 보유 수량을 사용한다. 모델 규칙은 읽기 확인했으며 각 사건을 연속 실행하는 즐겨찾기 UI 검증은 아직 별도다.
4. 일반 명령과 같은 실행: 즐겨찾기 선택이 기존 책략/도구 메뉴를 거쳐 대상·확정 경계로 전달된다. screen 합성 검사에서 즐겨찾기 책략도 일반 확인 전 MP/RNG를 소모하지 않음을 확인한다. 전직 도구 실제 비용까지의 경로는 추가 관찰 대상이다.
5. 메뉴 index/RNG: `OriginalBattleScreenTests`는 즐겨찾기 앞 삽입 후 대기 명령 동등성과 조회 MP/RNG 불변을 검사한다.
6. 이전 저장·ID·자료·UI: 자료 식별값이 추가되어 다른 자료/식별 없는 목록은 실행하지 않고 명시적 초기화 후 현재 자료에 연결한다. mismatch 편집 실패 불변/roundtrip 검사. 이전 저장 안내, 확대 글자/좁은 창 키보드 선택은 별도 UI 관찰 대상이다.

## 39 대사 검색·북마크

1. 실제 표시만 기록: `presentDialogue`의 표시 사건만 추가하고 source 전체 대사 목록을 색인하지 않는다. 인물·단어·장면 검색 모델 검사.
2. 같은 문장 별도 사건/재그리기: active ID·signature 재사용과 finish 후 새 사건 생성 검사.
3. 한도: 최근 300개 초과 후 북마크 보존, 201번째 북마크 원자적 거부 검사.
4. 저장: 하나의 F3 값 roundtrip·옛 저장 빈 이력·과거 snapshot 복원 검사.
5. 닫기 복원: `presentLog`는 현재 대사를 유지한 채 별도 overlay를 열고 responder를 복원한다. `CanvasOverlaySuspensionTests`는 남은 시간/중첩 일시정지를 검사한다. **검색 왕복의 실제 대사·남은 시간·초점은 별도 UI 관찰 대상**이다.

## 40 주변 찾기

1. 현재 표시 대상: 실제 배치 actor와 현재 walk marker만 투영; 플레이어·숨겨진 지도 제외 검사.
2. 같은 경로/접촉: UI가 `OriginalExplorationInput.townActor/townCell`로 미리보기 후 기존 `host.talk/walk` 실행 경계로 연결된다.
3. 이동 인물/다중 입구: 같은 marker의 두 셀을 별도 유지하는 합성 검사; 실행 전 현재 map 및 실제 actor 위치에서 다시 계산한다.
4. 조회 불변: 목록/경로 투영은 값 읽기이며 실행 버튼 전 `walk/talk`를 호출하지 않는다.
5. 도착 뒤 선택·구매: 기존 Host 대사/상점 경계를 사용자에게 반환한다. **직접 클릭 대 목록 이동의 실제 OS 경로 대조는 추가 관찰 대상**이다.

## 41 방문 상점 기록

1. 표시 경계에서만 `observeCurrentShopStock`; 원본 미래 재고 순회로 기록을 채우지 않는다.
2. 가격은 관측 시점 값, UI는 마지막 확인 정보라고 표시한다.
3. 같은 상점의 재방문 최신 관측 교체·동일 화면 중복 방지 합성 검사.
4. 과거 snapshot은 과거 가격/관측만 유지하는 roundtrip 검사.
5. 현재 장·방문 가능 도시·자료 식별값이 모두 맞아야 도시 연결; 식별 불일치 과거 물품은 당시 텍스트만 보여주고 현재 효과를 재해석하지 않는 검사.

실제 상점 방문→기록 검색→가능한 도시 이동 및 이전 저장 복귀 UI는 추가 관찰 대상이다.

## 42 통합 검색

1. 이름/명시적 효과 태그: 혼란 회복·병력 회복 합성 검색 검사.
2. 미공개 정보 제외: caller가 넘긴 동료, 보유/관측 물품, 습득 가능한 책략만 색인하는 검사.
3. 보유/습득 표시: 매번 현재 인물/물품에서 재생성, 과거 저장에서는 이후 상점 물품 제거 검사.
4. 상세 왕복: query/kind/filter/선택 index를 callback에 보존하고 기존 장수 상세에 연결한다.
5. 조회 불변: 값 투영만 수행하며 RNG/행동 경계를 호출하지 않는다. 검색 입력은 NSAlert의 text field가 소유한다.

검색어·선택 위치의 실제 왕복과 입력 중 단축키 차단은 추가 UI 관찰 대상이다.

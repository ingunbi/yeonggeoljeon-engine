# 개발 완료 기준과 검증 계획

기준일: 2026년 11월 9일. [42개 개발 계획](README.md)에 적용할 검증 절차다. 아래 명령과 시나리오는 기능 구현 이후 수행할 계획이며, 이 문서 작성으로 검사 통과나 캠페인 완주를 주장하지 않는다.

## 현재 검증 범위

[프로젝트 README](../../README.md)의 기존 기록상 정상 수치·합법 입력 경로는 새 게임부터 초반 여섯 전투 승리 후 다음 전투 진입까지 연결되어 있다. 별도 후반 저장에서 제3장 전투 승리·제4장 진입·다음 전투 진입을 확인한 경로도 있다. 두 경로를 합쳐 새 게임부터 엔딩까지의 정상 완주라고 판단하지 않는다.

README의 강화한 시험 봇 경로는 시나리오 도달 확인과 구분한다. 일반 수치의 정상 플레이와 사람의 실제 창 조작을 대체하지 않는다. 원작 저장에서 엔딩 직전 장면을 읽은 것은 마지막 전투를 정상적으로 승리한 검증과 다르다. 최신 실행 결과가 생기면 [08번](features/08.md)의 범위 기록을 갱신한다.

## 증거 수준

| 수준 | 증명하는 것 | 증명하지 않는 것 |
|---|---|---|
| 소스와 문서 검토 | 호출 경계·설계·자료 출처와 연결 관계 | 실제 실행 성공 |
| 합성 검사 | 원작 자료 없는 규칙·오류·저장 경계의 재현 | 실물 자료 전체 지원 |
| 고정 입력 재생 | 지정한 자료·수치·입력·난수에서의 동일 상태 | 실제 OS 입력이나 다른 모든 분기 |
| 화면 그리기 검사 | 지정 화면의 배치와 렌더 결과 | Finder 실행·포커스·마우스·키 전달 |
| 실제 창 조작 | 관측한 실행·입력·화면·저장 흐름 | 전체 캠페인·다른 모든 설정 |
| 정상 캠페인 경로 | 해당 시작점에서 종료점까지의 정상 진행 | 확인하지 않은 다른 선택·전투 경로 |

원본 DOS 실행 파일은 실행하거나 변경하지 않는다. 따라서 이 계획의 검증을 원본 런타임과 직접 비교한 결과나 픽셀 단위 일치로 표현하지 않는다.

## 구현 전 준비

1. 변경할 기능 문서의 완료 기준, 기존 테스트, 관련 심볼을 읽는다. 다른 작업의 변경은 보존한다.
2. 공개 검사는 합성 입력으로 구성한다. 실물 검사는 호출자가 명시한 원본 디렉터리와 별도의 빈 출력 폴더를 사용한다.
3. 실제 사용자 세이브는 검사 입력으로 읽더라도 원본 파일을 직접 덮어쓰거나 중단 저장을 소모하지 않는다. 격리된 복사본·저장 루트·앱 설정을 사용한다.
4. 실물 검사 전후 원본 파일과 보존 대상 세이브의 해시를 비교한다. 경로·해시·대사·화면 증거는 무시되는 로컬 폴더에 보관한다.
5. 현행 상태와 예상 차이를 기록한다. 새 편의 기능의 조회를 넣어도 전투 수치·RNG·실제 입력의 결과가 같아야 하는지 먼저 정한다.

## 자동 검사와 실행 경로

원작 파일 없는 기본 검사는 다음 기존 명령을 사용한다. 관련 검사부터 수행하고 변경 범위에 맞춰 전체 검사를 진행한다.

```sh
python3 -m unittest discover -s Tests -v
swift run yeonggeoljeon-engine --self-test
python3 tools/audit_source.py --output build/source-audit.json
```

등록 위치는 [main.swift](../../Sources/YeonggeoljeonEngine/main.swift)의 `--self-test` 분기다. 저장·중단 저장·책략 상세·대사·전직·전투 기록 검사와 초기 설정의 새 프로세스 검사가 이미 등록되어 있다. 기능별로 실패를 설명할 수 있는 검사를 추가하고, 구현을 그대로 반복하는 검사만으로 완료 처리하지 않는다.

실물 입력 재생은 [OriginalPlayVerification.swift](../../Sources/YeonggeoljeonEngine/OriginalPlayVerification.swift)의 허용된 플레이어 입력과 기존 CLI를 사용한다. 예시 경로는 호출자가 실제 경로로 지정한다.

```sh
swift run yeonggeoljeon-engine --data /path/to/GameData --verify-play --inputs /path/to/local-inputs.json --output /path/to/new-play-report
swift run yeonggeoljeon-engine --data /path/to/GameData --verify-play --resume /path/to/native-save.json --inputs /path/to/rest.json --output /path/to/new-resume-report
```

전투 승리·위치·능력·플래그를 검사기가 주입하지 않는다. 패배도 정상 결과로 기록하고, 실패 경로의 입력이나 결과를 지워 통과처럼 보이게 하지 않는다. 같은 입력 경로의 무중단 실행과 저장 후 재개를 비교한다.

| 기능군 | 반드시 확인할 사례 |
|---|---|
| F1 예측과 전술 | 다른 위치·장비·날씨에서 유효 대상 일치, 확률과 확정값 구분, 반복 조회 후 RNG 불변, 가상 이동 점유 처리, 스크립트 개입 경계 |
| F2 조건과 설명 | 여러 불가 이유 동시 발생, 비활성 행의 설명 접근, 숨김 적의 정보 유출 방지, 정수 계산 순서, 오래된 대상 재검사 |
| F3 저장 | 기존 형식 읽기, 라벨만 손상, 본문 손상, 미래 버전, 공간·권한·잠금·교체 실패, 취소, 동일 요청 중복, 중단 성공 후 소모 |

| F5 화면과 입력 | 실제 키·클릭·호버·Esc, 모달 닫기 클릭 누출, 설정 초기 로드, 창 크기·Retina·원작 틀·엔진 틀, 포커스 이탈과 저장 예약 |

20번의 모드별 비교는 같은 원본 옵션워드에서 수행한다. `physicalPrelude`의 난수 소비에 영향을 주는 원본 옵션값은 보존하고, 새 표시 정책이 그 값을 변경하지 않는지 별도로 검사한다. 원본 옵션이 다른 실행끼리의 난수 일치를 완료 기준으로 삼지 않는다.

숨김 정보 검사는 실제 원본 적 위치를 공개 테스트에 넣지 않는다. 합성 보드에서 비공개 상태만 바꿨을 때 공개 출력이 부당하게 달라지는지 확인한다. 시나리오가 의도적으로 드러내는 정보를 어느 경계에서 공개하는지도 구분한다.

## 실제 창에서 확인할 기본 경로

각 구현 묶음에서 관련 경로를 반복한다. 앱 프로세스 실행과 화면 관측을 함께 남기며, 렌더 PNG만 생성한 것을 실제 입력 검증으로 부르지 않는다.

1. 앱이 꺼진 상태에서 실행한다. 기본 설정과 대사 자동 넘기기가 켜진 설정을 각각 확인한다. 초기 알림 재진입으로 실행이 멈추지 않아야 한다.
2. 새 게임의 대사를 건너뛰고 첫 전투에 진입한다. 승리조건 직전 마지막 대사가 처음 나타날 때부터 비어 있지 않은지 확인한다. 순간 결함은 연속 화면 기록으로 판별한다.
3. 아군 선택·경로 호버·명령·대상 선택·Esc 취소를 반복한다. 이전 부대의 예측과 도움말이 남지 않아야 한다.
4. 키보드와 마우스로 같은 저장 목록에 진입한다. 읽기 전용 원작 슬롯과 일반 슬롯, 단일 소모형 중단 슬롯이 명확히 구분되어야 한다.
5. 수동 입력 시점, 공격·이동 연출 중, 적 턴 중에 중단 저장을 요청한다. 대기·취소·오류·타이틀 복귀와 이어하기 성공 후 소모를 확인한다.
6. 저장 예약 중 창 닫기·⌘Q·다른 앱으로 전환을 조합한다. 자동 일시정지 때문에 저장 경계가 막히거나 종료가 반복되지 않아야 한다.
7. 창 크기와 배율, 글자 크기, 표시 모드를 바꾸고 메뉴·미니맵·지도 선택을 확인한다. 대사와 선택 상태를 유지해야 한다.
8. 실패 또는 취소 뒤 현재 게임으로 돌아온다. 조작 불가 상태, 닫히지 않는 모달, 이미 소모된 행동의 재실행이 남지 않아야 한다.

실제 앱 설정을 사용한 경우 원래 값으로 복원하고 복원 여부를 기록한다. 테스트용 사용자 데이터와 실제 게임 데이터의 경로를 혼용하지 않는다.

## 결과 기록 형식

로컬 실행 보고서는 `build/` 또는 `research/local/` 아래에 둔다. 다음 항목을 포함한다.

- 기능 ID, 코드 버전·소스 해시, 실행일, 검증 환경과 설정.
- 합성·고정 입력·실제 OS 입력 중 수행한 종류와 각 결과.
- 입력 자료의 식별자와 해시, 시작 상태, 선택 경로, 종료 상태, RNG 비교 범위.
- 원본·기존 저장 보존 결과, 테스트 설정 복원 여부.
- 통과·실패·건너뜀·미검증을 나눈 기준별 결과와 오류 재현 방법.
- 기능 문서의 어느 완료 기준을 충족했는지와 아직 남은 경계.

공개 문서에는 원본 대사·그림·지도·세이브·사용자별 절대 경로를 복사하지 않는다. 공개 합성 검사에는 인위적으로 만든 입력을 쓴다. 배포 전 정확한 소스 목록을 감사하고, 로컬 빌드나 소스 감사 통과를 공개 배포 또는 게임 전체 완성으로 표현하지 않는다.

## 문서 변경만 있을 때

문서 작성에는 게임 실행과 세이브 조작을 요구하지 않는다. 42개 항목의 누락·중복, 우선순위와 단계의 일치, 선행 기능의 순환 여부, 링크 대상 존재, 기존 기능과 제안 기능의 구분, 공개 소스에 포함할 수 없는 자료의 혼입을 검토한다. 이 검토 결과는 기능의 실행 검사 결과와 분리한다.

# 저장 질문, 타이틀 메뉴와 네이티브 이어하기

고정한 한국어 DOS/V MAIN 프로파일에서 얻은 정적 분석이다. 원작 프로그램은
실행하지 않았다. 오프셋은 MAIN.EXE 파일 오프셋이다.

## 원작 흐름

원작 명령 `3D`는 `0x22A62..0x22AA1`을 실행한다. 두 버튼 선택기(`CF5:3C5E`,
모드 2)로 DS:`305A` 질문을 묻는다. 예는 `CF5:F0CE`를 반복하며, 이 루틴은
`CF5:BDBA`(`0x1F70A..0x1F781`)를 거쳐 슬롯 대화상자 `CF5:B58C`를 저장 모드
`0x100`으로 연다. 저장을 취소하거나 실패하면 DS:`3073` 거절 확인을 묻고, 그
아니오는 슬롯 대화상자로 돌아간다. 그 뒤 핸들러가 0을 반환하므로 원작 커서는
`3D` 다음으로 진행한다.

MAIN의 메뉴 `CF5:C050`(`0x1F9A0..0x1FA17`)은 DS:`2D38` 항목 네 개를 보이고
DS:`2CEC` 핸들러로 분기한다. 새 게임(`CF5:B536`), 이어하기(`CF5:BDAE`, 1과
`0x100`으로 `CF5:BD1E`를 호출), 설정(`CF5:BFDE`), 오프닝(`CF5:C012`)이다.
main은 고른 인덱스를 프레임워크 루프에 넘긴다. 0이 아닌 인덱스는 첫 진입
플래그를 세우고 `CF5:C456`(`0x1E1E2..0x1E284`)을 호출한다. 항목 3은 종료 코드
0을 반환하므로 HERO.COM은 OPEN을 실행한 다음 MAIN을 다시 실행한다. 원작 슬롯은
`MSAVE0..4.R3S`이다.

필드 시스템 메뉴(`0x22CD2..0x22DB6`)는 DS:`34E8` 항목 열 개를 나열하고
DS:`3478` 핸들러로 분기한다. 세계지도와 거점의 입력 표(DS:`3636`, DS:`36E2`)가
입력 코드 `23`을 이 메뉴로 보낸다. 종료(`CF5:F044`)는 DS:`3018`을 묻고 맵 루프
플래그 `40`을 세운다. 불러오기는 `CF5:F152`이고, 저장은 `3D`와 같은 슬롯 루틴
`CF5:F0CE`를 호출한다. 나머지 항목은 스크롤, 속도, 모니터, 음악, 효과음을
설정한다.

## 네이티브 대응

생성기는 push/call 순서를 확인한 뒤 메뉴 문구 네 개와 저장 질문 두 개를 로컬
GameData로 내보낸다. 캠페인 창은 오프닝이 끝나는 즉시 메뉴를 보인다([타이틀
메뉴](original-title-menu.md)). 새 게임은 원작 프로그램을 시작하고, 이어하기는
슬롯 목록을 열고, 설정은 MAIN의 타이틀 옵션 세 개를 열며, 오프닝은 오프닝을
다시 재생한다.

유휴 상태의 마을, 궁전, 세계지도에서 보조 클릭을 하면 내보낸 라벨로 필드
메뉴가 열린다. 종료는 마스크 `40`을 거쳐 재시도 선택기에 이른다. 불러오기와
저장은 네이티브 슬롯 다섯 개의 목록을 연다. 목록의 한 행으로 어느 위치의
이어하기 파일이든 불러올 수도 있다. 옵션은 아래에 설명한다. 입력 코드 `23`의
원작 물리 키 배정은 확인되지 않았다.

원작 `3D` 질문에서 창은 원작 질문을 묻고, 사용자 Application Support 폴더 아래
슬롯에 `OriginalCampaignResume` JSON 파일을 쓴다. 이것은 MSAVE 슬롯이 아니라
네이티브 엔진 상태다. 원작 슬롯에는 절대 쓰지 않는다. 불러오기 목록은 [세이브
노트](original-saves.md)에 적은 대로 원작 슬롯도 읽기 전용으로 가져온다. 네이티브 슬롯은 자체 제목과 날짜를 가진다. 이어하기 지점은
스테이지가 전투 팔레트 밖에서 유휴 상태이고 다른 원작 동작이 호스트를 점유하지
않을 때만 만든다. 즉 대기 중인 `3D`에서, 또는 실행 중인 스크립트가 없는 유휴
필드 컨트롤러에서다(필드 메뉴 저장이며, 저장 오프셋 없이 기록한다). 이 지점은 대기 중인 `3D`를 포함한 VM 상태, 공유 인물 객체,
명단, RNG, 금전, 스테이지 스냅샷, 파티 이월 상태, 원작 `36` 체크포인트, 불확실
복귀 표시, 컨트롤러 계속 플래그를 보존한다. 이어하기는 이 값들을 복원하고,
저장된 맵을 설정하고, 유휴 스테이지를 복원한 뒤, 대기 중인 `3D`를 저장을 수행한
것으로 완료한다. 필드 저장은 유휴 필드 컨트롤러를 재개한다.

MAIN 자체의 불러오기 경로(슬롯 대화상자, `CF5:C456`, 첫 진입 배치)는 재현하지
않았다. 따라서 네이티브 이어하기는 원작 불러오기 경로로 맵에 다시 들어가지 않고
저장된 네이티브 스테이지를 복원한다.

## 검증

`--verify-play`는 `save-native` 입력과 `--resume FILE` 옵션을 받는다. 로컬에서
138개 입력으로 된 입력 재생의 저장 지점 세 곳(첫 전투 전, 그 전투 후의
세계지도, 1장 세계지도)을 저장하고 이어했으며, 궁전을 나온 뒤 1장 마을에서 필드
메뉴 저장을 한 번 했다. 이어한 각 실행의 최종 체크포인트는 스테이지 명령 커서를
제외하면 중단 없는 실행과 같다. 이어한 첫 프레임은 같은 지점의 중단 없는
프레임과 일치했다. 합성 테스트는 유휴 스테이지 복원, 유휴가 아니거나 일관되지
않은 스냅샷의 거부, 전부 아니면 전무인 인물 교체, 타입 지정 파일 읽기를 다룬다.
AppKit 메뉴와 패널은 실제 macOS 입력으로 조작하지 않았다.

## 옵션

객체 DS:`7A80`은 플레이어 옵션을 담으며 `1A406`에서 만들어진다(속도 2, 스크롤 1,
워드 `+4`는 0). `OriginalSettings`는 이를 사용자별로 보관하므로 입력 재생과
테스트는 항상 원작 기본값으로 실행한다.

| 항목 | 원작 | 네이티브 효과 |
| --- | --- | --- |
| 스크롤 단위 | `22832`, 바이트 `+11` | DS:`2FEC`의 라벨(소·중·대·극대)이 1, 2, 4, 8 중 하나를 고른다. 필드 루프는 이 값을 `0:4F68`(`24212`)로 CS:`14FE` 레코드 0의 바이트 `+11`에 쓴다. 레코드 0의 `+E`/`+F`는 지도 창 왼쪽 위의 16픽셀 칸 좌표다. `210CE`는 지도 창 안 포인터 칸에 이 값을 더해 가리키는 지도 칸을 구한다. 세계지도 입력(`23EBC`)은 입력 코드 1..8에서 `0:4F8E`를 불러 이 좌표를 여덟 방향 중 하나로 단계만큼 옮기고, `+C`/`+10`에서 멈춘다. 엔진은 세계지도 카메라를 같은 단계로 옮긴다. 포인터가 지도 가장자리 12픽셀 안(현대 화면은 캔버스 가장자리와 그 바깥 여백)에 머물면 1/15초마다 한 단계, 방향키는 누를 때마다 한 단계다. 코드 1..8 영역의 위치와 `CF5:DE90`/`EBFE`가 정하는 반복 시점(머무름인지 클릭인지)은 확인하지 않았으므로 가장자리 폭과 반복 간격은 엔진 선택이다. 정적 분석이며 원작 실행과 비교하지 않았다. 스크롤은 보기 상태라 저장과 입력 재생에 들어가지 않고, 다음 이동이 카메라를 다시 맞춘다. |
| 속도설정 | `22BFE`, 바이트 `+13` | 필드 루프는 속도 x 3틱을 기다리므로(`24818`) 보통은 이미 알려진 6틱이다. 필드 시간은 2/속도 비율로 변한다. 노웨이트는 대기가 없으며, 엔진은 보통의 6배를 쓴다. |
| 모니터 | `229AE`, 워드 `+A` 비트 8 | 캔버스 전체에 거는 회색 필터. 캡처한 화면에는 이 필터가 나타나지 않으므로 직접 살펴보지 않았다. |
| BGM, 효과음 | `228C6`, 워드 `+A` 비트 2와 1 | 오디오 스위치. |
| 음량 | `22BCE` | 핸들러 인덱스 8은 음량이라는 라벨 아래에서 DS:`343C`의 음악·효과음 테스트 목록을 연다. 엔진은 의미에 맞춰 대응한다. 이 행은 출력 음량 하나를 정하며, 엔진에 추가한 기능이다. |
| 음악시간 | 핸들러 인덱스 9 | DS:`343C` 목록. DS:`312E`의 곡과 DS:`3364`의 효과음이며, 그 이름이 모든 사운드 id도 문서화한다. |
| 부대전투 | `27DC4`, 워드 `+4` 상위 니블 | 0이면 확대 화면을 재생한다([original-combat-view.md](original-combat-view.md)). 0이 아니면 이를 건너뛰고, 원작처럼 맵 효과와 서두 그리기를 두 배로 한다. |
| 이동속도 | `27E2C`, 하위 니블 | 전투 애니메이터의 걷기 이동 폭. |
| 적의 이동 | `27774`, 비트 `1000` | 카메라가 적의 걷기를 따라간다(`2C4D6`). 끄면 엔진은 보이는 칸이 없는 걷기를 건너뛰지만, 원작은 그 시간도 그대로 쓴다. 원작 새 게임은 이 비트가 꺼진 상태(본다가 아님)로 시작하지만, 엔진 창은 켠 상태(본다)를 기본으로 쓴다. 설정 리비전 1 이전에 저장된 설정도 한 번 켜고, 그 뒤 고른 '안 본다'는 유지한다. 입력 재생과 검증은 사용자 설정을 읽지 않으므로 원작 값 0을 쓴다. |

## 엔진 추가 기능

다음 기능은 원작에 대응하는 것이 없으며 게임 상태를 절대 바꾸지 않는다.

- 필드는 유휴 필드의 장면이나 맵이 마지막 자동 저장과 다를 때마다
  `Saves/slots/auto.json`을 쓴다. F5와 F9(또는 게임 메뉴)는 `quick.json`을 쓰고
  읽는다. 둘 다 다섯 슬롯과 같은 이어하기 형식을 쓰며 불러오기 목록에 나타난다.
- Control을 누르고 있으면 필드, 전투 애니메이터, 교전 화면의 프레임 단계가 네
  배가 된다. 일반 대사는 6프레임 뒤에 닫힌다. 질문, 목록, 선택지는 여전히
  기다린다.
- 대화 기록은 창에 표시된 마지막 300줄을 보관한다.
- 전투 재생 배속(기능 메뉴, 보통·1.5배·2배·3배)은 지도 걷기를 포함한 전투
  애니메이터, 확대 전투 화면, 일기토, 전투 알림의 재생을 빠르게 한다. 지도 이동
  속도는 걷기 폭을 정하는 별도 설정이며 두 설정이 함께 적용된다. 필드 속도설정과는
  구분되며 게임 상태와 난수에는 영향이 없다. 현대 메뉴에는 선택 항목별 설명을 표시한다.
- 기능 메뉴와 필드 메뉴의 설정 줄은 현재 값을 오른쪽에 보이고, 클릭이나 ←→로
  하위 메뉴 없이 바로 바꾼다. 저장되는 값은 원작 선택 창과 같다.
- 세계지도에서 플레이어가 고른 행군은 카메라가 부대를 따라간다(도착하면 멈춤).
  원작이 이 행군에서 화면을 어떻게 움직이는지는 확인하지 않았으며, 스크립트의
  추적 명령(`0x3C`, MAIN2259C)은 그대로 따른다.
- 마을·세계지도에서 막힌 칸을 누르는 식의 거부된 입력은 화면에 영어 내부 문구를
  띄우지 않고 콘솔에만 남긴다. 저장·불러오기 실패만 한글 안내를 보인다. 전투의 거부는
  한글 이유만 접두어 없이 보이고, 엔진 진단은 콘솔로 보낸다. 캠페인이 멈춘 경우의
  이유는 그대로 보인다.
- 자동 넘기기의 남은 시간 막대는 그리지 않는다.
- 타이틀 메뉴는 메뉴 바깥 클릭으로 취소되지 않는다. 원작처럼 취소하면 종료 화면을
  거쳐 게임이 끝나므로, 취소는 Esc나 오른쪽 클릭으로만 한다.
- 자동 넘기기(A, ⌘E)는 입력을 기다리는 줄이 다 보인 뒤(글자는 초당 60자로 나타남)
  정해진 시간이 지나면 입력 한 번처럼 줄을 닫는다. 느리게는 `0.8 + 0.04 × 글자 수`초
  (1.2~5초), 보통은 `0.4 + 0.02 × 글자 수`초(0.8~2.5초), 빠르게는 `0.15 + 0.01 × 글자 수`초
  (0.4~1.5초)다. 필드 메뉴와 전투 기능 메뉴의 '대사 자동 넘기기' 줄에서 끔·느리게·보통·빠르게를
  고른다. 원작이 스스로 닫는 0B/0E 상자는 원래 시간을
  그대로 쓴다. 이 선택은 플레이어 설정에 남고 입력 재생과 시험은 꺼진 상태로 실행한다.
- 건너뛰기(S, ⌘K)는 필드와 전투의 프레임 단계를 여덟 배로 하고 매 프레임 줄을 닫는다.
  질문·목록·승리조건 창, 전투의 명령 차례, 마을과 세계지도의 조작 지점에 오면 저절로
  꺼진다. 둘 다 창이 입력을 보내는 시점과 시간 진행 속도만 바꾸며 원작 난수를 따로 뽑지
  않는다. 고정 단계 입력 재생은 이 기능을 쓰지 않고, 결과는 이전과 같다.
- 공격 대상 지정 중에는 사거리 안의 각 적에 일격의 피해와 반격 확률을 보인다.
  일격은 난수를 뽑지 않는다(`0x31474`). 반격은 방어 측 공격 스칼라를 150 미만의
  난수와 비교하므로, 원작이 반격을 허용하는 경우 확률은 그 스칼라를 150으로 나눈
  값이다.
- D(또는 ⌘D)는 보이는 적이 이번 턴에 칠 수 있는 모든 칸을 칠한다. 플레이어 자신의
  이동 규칙에 따른 그 적의 이동 범위를 구한 뒤, 도달 가능한 각 칸에서 병과 공격
  범위를 적용한다. 책략과 AI 지시는 제외하므로 물리 공격에 대해서만 상한이다. 숨은
  적은 아무것도 더하지 않는다.
- Tab과 Shift-Tab은 아직 행동할 수 있는 다음 또는 이전 아군 부대를 클릭했을 때처럼
  선택하고 화면 중앙에 둔다.
- 캠페인에서는 그런 부대가 남아 있는 상태로 아군 페이즈를 끝내면 먼저 확인을
  묻는다. 원작의 턴 종료 항목은 즉시 끝낸다(`27D12`).
- 포인터 아래의 부대가 상태 줄에 표시된다.


## 엔진 전투 시작 저장

2026-11-07: `OriginalCampaignResume.battleStart`는 원작 MSAVE 기능이 아닌
엔진 편의 기능이다. 기존 필드 저장 형식 1에는 이 선택 필드가 없으며 그대로 읽는다.
오프닝 스크립트와 이동·일기토가 모두 끝나고, VM과 호스트가 입력 대기이며
`OriginalTurnStage.unstarted`인 경계에서만 캡처한다. 진행 중 공격·AI·이동 취소
스택을 저장하거나 전투 중간에서 이어지는 것처럼 표시하지 않는다.

저장에는 canonical 인물·배치·난수·턴·live unit뿐 아니라 오프닝이 변경할 수 있는
지형·그림 타일·script action state를 담는다. 복원 시 원본 프로그램의 지도 전환
명령과 전투 ID를 검증하고 새 전투 세션을 구성한 뒤 저장 상태를 복원한다.
캡처 단계에서 실제 재구성 가능 여부를 확인하며, 파일 쓰기 성공 뒤에만 UI가
저장 완료로 표시한다. `battle-start`는 일반 다섯 슬롯·자동 저장·빠른 저장과
분리된 엔진 슬롯이다. 이후 전투의 시작 상태가 저장되면 이 슬롯을 갱신한다.

검사는 `OriginalResumeTests.swift`의 합성 상태/거부 검사와 호출자가 고른
로컬 원본 입력 재생의 저장 전후 비교로 구분한다. 이러한 비교는 자체 엔진의
고정 스텝 상태 비교이며 원작 DOS 실행 비교나 사람이 캠페인을 완주한 검증은 아니다.

같은 날 선택한 로컬 입력132개로 `0:0:5`, `0:0:7`, `1:0:6`의 첫 턴 경계마다
JSON 쓰기·읽기·복원을 수행했다. 연속 실행과 복원 실행은 관측 기록 전체와
최종 상태(재구성 시 폐기하는 화면 명령 커서 제외)가 같았다. 세 전투 모두
`preserveFriendlySlots=false`이므로 아군 배치를 유지하는 연속 전투의 복원은
이 실제 자료 검사 범위에 포함되지 않는다. 기존138개 입력의 다음 공격은
사거리 밖으로 거부되며, 그 중단 기록도 로컬에 남긴다.

## 별도 중단 저장

2026-11-07 사용자 선택: 일반 저장과 분리된 한 칸에 중단 저장한 뒤 타이틀로
돌아가며, 이어하기 성공 시 파일을 소모한다. 기존 필드 빠른 저장 파일은 보존하고
불러오기 목록에 남긴다. 저장소는 `Saves/suspend.json`에 메타데이터와 snapshot을
한 번에 원자 기록한다. 프로세스 간 잠금과 확인 시점의 저장 ID 검증으로 중복 소비를
거부한다. 새 호스트와 화면 구성이 실패하거나 파일 삭제에 실패하면 기존 플레이와
중단 파일을 유지한다. 원작 MSAVE 동작을 복원했다고 주장하지 않는다.

`OriginalCampaignResume.suspension`은 필드의 대사·선택 및 전투 수동 입력 경계의
추가 상태를 보존한다. 이동 취소 원점과 이미 전달한 전사 통지, 난수와 턴·행동 상태도
복원한다. 실제 공격·책략·도구 연산과 AI 실행은 원자적으로 끝나야 하며, UI의 연출도
마친 뒤 저장한다. 상점·출전·도구 선택과 진행 중인 이벤트는 다음 지원 경계까지
요청을 대기시키며 플레이어의 답을 대신 선택하지 않는다. 타이틀·엔딩·오류 상태는
지원하지 않는다. 글자 나타내기와 카메라·선택 표시 같은 화면 표현은 재구성한다.

이 규칙은 반복 불러오기를 줄이는 편의 정책이며 외부 파일 복사를 방지하지 않는다.
원작 실행과 비교한 기능이 아니며, 저장 경계의 동일성과 이후 입력 재생은 합성 검사와
호출자가 선택한 로컬 자료 검사로 따로 확인한다.

로컬 검증에서는 132개 입력으로 세 전투를 진행하며 468개 경계에서 캡처를
시도했다. 411회는 별도 파일에 쓰기·읽기·단일 소비·복원을 완료했고, 57회는
진행 중인 동작 때문에 보류했으며 오류는 없었다. 이동 취소가 가능한 상태58회,
대사186회, 선택3회가 포함된다. 연속 실행과 중단 복원 실행의 관측 기록 전체 및
최종 체크포인트(폐기하는 화면 명령 진단 커서 제외)가 일치했다. 최종 설치본도
합성31그룹과 별도132입력 재생을 통과했다. 이는 고정 단계 자동 검증이며 실제 OS
키 입력으로 중단 저장부터 재개까지 확인하거나 원작 DOS 실행과 비교한 결과는 아니다.

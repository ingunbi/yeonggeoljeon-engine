# Yeonggeoljeon Engine · 영걸전 자체 엔진

![게임·XR·웹 개발을 표현한 공통 컨셉 표지](https://raw.githubusercontent.com/ingunbi/Unity_ClickerGame_Tutorial/main/docs/images/developer-workshop.png)

<sub>공통 소개 이미지 · AI로 제작한 컨셉 아트이며 실제 프로젝트 실행 화면이 아닙니다.</sub>

**원작 자료의 해석부터 전투 규칙과 캠페인 실행까지, Swift로 만드는 자체 SRPG 엔진.**

한국어 DOS/V판 삼국지 영걸전을 연구하며 자료 해독기, 게임 상태와 규칙, 네이티브 화면을 연결합니다. 공개 코드는 연구 개발 중이며, 전체 캠페인의 사람에 의한 완주 검증은 아직 없습니다.

| 살펴볼 부분 | 내용 |
| --- | --- |

[실행 준비](#macos-빌드) · [개발 계획](BACKLOG.md) · [구현 근거](research/README.md) · [iPad 개발](docs/ipad-testing.md)

**공개 범위:** 새 엔진 코드·문서·합성 테스트입니다. 원작 게임 자료와 이를 포함한 앱은 배포하지 않습니다. 실행에는 사용자가 보유한 자료가 필요합니다. 새 코드는 GPL-3.0-only이며 원작 콘텐츠 권리는 포함하지 않습니다.

## 개발·실행 상세

[![Engine source checks](https://github.com/ingunbi/yeonggeoljeon-engine/actions/workflows/verify.yml/badge.svg)](https://github.com/ingunbi/yeonggeoljeon-engine/actions/workflows/verify.yml)

한국어 DOS/V판 삼국지 영걸전의 원본 자료와 정적 분석을 바탕으로 만드는
Swift/AppKit 자체 엔진입니다. **0.4.0 연구 개발판**은 원작 전투 계산·AI·책략과
캠페인 실행기를 복원하는 단계입니다. 첫 전투부터 엔딩까지 이어서 플레이할 수 있지만, 사람이 끝까지 해 본 검증은 아직 없습니다.

공개 저장소에는 새 엔진 코드·문서·합성 테스트만 들어 있습니다. 원작 실행 파일,
그림·음악·대사·지도·시나리오·수치표와 이를 담은 앱은 포함하지 않습니다.
사용자가 보유한 자료를 지정하면 자신의 컴퓨터에서 실행 자료를 생성합니다.
이전 공개 엔진 기반 시험 앱과 분리했으며 그 코드·콘텐츠 팩·대체 에셋을 사용하지 않습니다.

[개발 예정 목록](BACKLOG.md)과 [우선순위·상세 개발 문서](docs/development/README.md)에서 플레이 보조와 편의·안정성 개선 42개 과제의 범위·개발 순서·완료 기준을 관리합니다.

[iPad 독립 실행 문서](docs/ipad-testing.md)에서는 공용 Swift 엔진에 연결한 SwiftUI/UIKit 터치 화면, 별도 저장 공간, 로컬 서명 빌드와 실기기 검증 범위를 관리합니다. 맥용 AppKit 화면과 구분하며, 개발 앱 설치를 전체 게임 검증 완료로 표현하지 않습니다.

## 현재 구현

| 부분 | 구현과 한계 |
|---|---|
| 원작 자료 해독 | LS11·NPK·TF-DCE·planar 자체 해독. 궁전23·마을12·세계지도4·전투지도58, 삽화38·초상화240과 인물384개 연결. 결과는 로컬에만 생성. |
| 원작 전투 수치 | 병과·레벨·장비·사기 기반 능력, 상성·지형·병력 피해, 반격, 경험치·레벨 상승, 사기·상태이상·회복·MP. 인물 상태는 캠페인과 유닛이 공유. |
| 원작 책략 | 0~35 명령의 사용 가능 조건, 피해·상태·사기·단일/범위 회복, 확산 순서·비용·경험치. 실제 명령과 AI 예상 점수를 분리. |
| 전투 도구 | 속성 변경·전직, 공격서, 혼란서, 단일/범위 회복, 폭탄의 조건·대상 범위·난수 순서·소모. 거부와 취소는 도구와 행동을 소모하지 않음. |
| 필드 기능 | 장수 정보, 장수 간 도구 교환, 세계지도의 전체 지도와 도시 선택 이동, 스토리 정보. 세계지도는 포인터를 가장자리에 대거나 방향키를 누르면 필드 메뉴의 스크롤 단위(소·중·대·극대 = 1·2·4·8칸)만큼 스크롤. 엔진 안내로, 세계지도에서 지금 고를 수 있는 도시(원작 도시 깃발의 하위 두 비트가 모두 켜진 도시)에 이름표를 달고, 도시를 가리키면 원작 경로 계산으로 정한 행군 길을 점선으로 미리 보이며, 고를 수 있는 도시와 대화 상대 위에서는 손가락 포인터가 됨. 마을·궁전의 클릭은 걷기 칸을 32×16 마름모로 읽고(걷기 칸이 길 그림과 정확히 겹치는 배치), 막힌 곳을 누르면 건물이면 가까운 문으로, 길 옆이면 가까운 길 칸으로 맞춤. 가리키면 갈 칸에 마름모를 보이고 문이면 '들어가기'·'나가기'·'마을 밖으로'를 띄우며, 클릭한 칸에는 잠깐 표시가 나타남. 세계지도에서 고른 행군은 화면이 부대를 따라감. 필드 메뉴는 세이브·로드를 위에, 게임 종료를 맨 아래에 두고 설정 줄을 제자리에서 바꿈. 출전 선택은 장수 능력을 함께 보여 주는 창으로 표시. |
| 음악 | 코에이 드라이버(SBOPL2.COM)의 곡 해석기를 옮기고 OPL2 합성기를 자체 구현해 MUSIC.R3 20곡을 원작 선택 그대로 재생. 필드·전투 메뉴의 BGM으로 켜고 끔. 효과음 43개와 오프닝·엔딩 음악도 재생. 곡이 바뀔 때는 원작처럼 이전 곡을 약 0.6초 동안 줄인 뒤 바꿈. 그 밖의 페이드와 페이드 동안의 진행 멈춤은 미복원이고, 음량은 엔진이 정하는 출력 음량 하나. |
| 도구상 | 세계지도 도착 시 입장 질문, 원작대로 종류 7인 궁전 방(10·11번, 마을마다 상점 문 하나)의 상인 배치와 방 음악, 세계지도 기본 진입 곡, 도시별 재고, 구매·판매 가격, 소지금 상한, 장수별 8칸 소지품, 원작 문구와 구매·판매·거절 효과음. 원작 창 모양은 복원하지 않음. |
| 원작 이동·AI | 병과별 이동 비용, 진영 점유·ZOC, 원작 공격 패턴, 명령0~4의 목표·영향권·후보 평가, 물리/책략 비교와 후보별 RNG 소비. 미해석 점유 상태에서는 중단. |
| 원작 턴 | 날씨, 진영별 회복·상태 회복, AI 우선순위, 이동 취소·대기, 원작 턴 제한 결과와 캠페인 이벤트 프로브. 일반 전멸 판정으로 승리를 만들지 않음. |
| 캠페인 실행기 | 5장·18멤버·225블록·2,144레코드의 단계 그룹·반복·조건·플래그·선택·전환. 시나리오가 실행한 배치 프로그램을 사용하며 기록 목록의 다음 행으로 진행하지 않음. |
| 장면 실행 | 동일 런타임에서 인물 배치·동시 이동·퇴장·대사·원작 삽화·초상화를 유지. 도시/인물 입력은 경로·인접 판정·상호 방향 확인 뒤 원작 이벤트를 호출. 목적지 도착은 원작대로 기록 종류2(세계지도는 5)를 찾음. 일치 기록이 없으면 원작 내장 전환으로 방 입장·궁전 출구(복귀 문맥)·마을 출구(세계지도)를 처리하고 기본 플레이어를 배치. 장 제목은 원작처럼 짧은 상자로 보인 뒤 장 표시줄에 남고, 장소 이름과 획득 알림은 원작 시간(96틱, 약 1.6초) 뒤 저절로 닫히는 상자로 표시. 지도가 바뀔 때는 원작처럼 이전 화면이 약 0.53초 동안 어두워지고, 스크립트의 05 명령에서 새 지도가 밝아짐. 세계지도에서는 처음 배치한 부대(슬롯 0)와 행군하는 부대를 따라 원작 규칙대로 화면을 스크롤함. 전투에 들어가고 나올 때도 원작 순서대로 어두워졌다가 밝아지며, 전투 스크립트 이동·원군 등장도 부대 걷기와 카메라 이동으로 표시. 원작 창 테두리, 이야기 그림의 패턴 전환, 기본 진입 음악 일부는 미복원. |
| 저장·이어하기 | 원작 3D 저장 질문 시점과, 마을·세계지도에서 오른쪽 클릭으로 여는 원작 필드 메뉴(게임 종료·로드·세이브)에서 자체 엔진 상태를 JSON으로 저장하고 그대로 이어서 진행. 저장·불러오기 목록에서는 각 슬롯의 장·위치·주인공 레벨·금·동료 수를 함께 보여 줌. 오프닝이 끝나면 바로 원작 MAIN 메뉴(개시·재개·기능설정·오프닝)가 원작 문구로 뜸. 원작 화면 틀에서는 원작처럼 검은 화면에 MARK 그림으로 그린 MAIN의 메뉴 창을, 엔진 화면에서는 리메이크풍 시작 화면(흐린 타이틀 그림 배경, 원작 로고, 벚꽃 띠, 아이콘 버튼 새 게임·이어하기·환경 설정·오프닝 보기·종료, 키 안내)을 표시. 기능설정은 원작의 모니터·BGM·효과음 세 줄이며, 엔진 화면의 환경 설정은 여기에 대사 자동 넘기기를 더해 값을 바로 바꿈. 메뉴를 취소하면 원작처럼 종료 화면을 보인 뒤 게임이 끝남. 새로 시작과 불러오기는 원작처럼 약 0.53초 동안 어두워졌다가 밝아짐. 불러오기 목록에서 원작 세이브 슬롯(MSAVE·ESAVE)을 읽기 전용으로 가져옴. 원작 파일에는 쓰지 않음. |
| 편의 기능 | 원작에 없는 엔진 추가 기능. 대사 자동 넘기기(A·⌘E·대화창의 자동 버튼, 필드·전투 메뉴에서 끔·느리게·보통·빠르게를 고름. 문장이 다 보이면 보통은 글자 수에 따라 0.8~2.5초 뒤 넘어가고 설정에 기억), 선택·전투 진입까지 건너뛰기(S·⌘K·대화창의 건너뛰기 버튼, 8배속으로 대사를 바로 넘기다가 새 전투 진입·질문·목록·승리조건 창·전투 명령 차례·마을과 세계지도 조작 지점에서 저절로 멈춤), Control을 누르는 동안 4배 빨리 감기(대사는 0.1초 만에 넘김), 대사 기록, 장면·지도가 바뀔 때마다 자동 저장, 빠른 저장·불러오기, 공격·책략·도구 대상 위의 예상 피해·효과·성공률·반격 확률 표시, 적 공격 범위 표시, 다음 부대 선택, 행동하지 않은 부대가 남았을 때의 턴 종료 확인, 마우스를 올린 부대의 정보. 마을·궁전에서 마우스를 올린 인물의 이름표, 대사 글자가 차례로 나타나는 효과(첫 입력은 문장을 다 보여 주고 다음 입력이 넘김, 빨리 감기는 바로 넘김). |
| 게임 화면 | 원작 MAIN이 그리는 필드 화면 틀(PACKGRP 0번)과 우측 HUD(주인공 초상화·돈·레벨·현재영토)와 좌하단 위치 표시를 MAIN 명령의 좌표로 배치. 전투 화면 틀(1번)에는 13×11칸 스크롤 지도, 전투 이름, 세력 이름, 아군/적군 전환, 병력 막대가 붙은 부대 목록, 미니맵과 시야 사각형, 기능 메뉴, 승리조건 창, 빈 칸을 눌렀을 때의 지형 정보 창을 원작 규칙으로 표시. 부대를 고르면 이동 칸을 정한 뒤 원작 위치에 공격·책략·도구·대기 창이 뜨고, 취소하면 원위치로 돌아감. 부대 걷기, 칼 부딪힘, 화살·투석, 책략과 도구 효과가 원작 그림과 원작 타이머 단위로 재생되고, 공격마다 원작 확대 전투 화면(지형별 배경, 병력 수에 따른 병사, 결과 창)이 나옴. 클릭은 대기 단계를 넘기고, 오른쪽 클릭이나 Esc는 장면을 끝냄. 도구는 사용·건네기·버리기·보기를 복원. 저장 질문·재시작·선택지·타이틀/필드 메뉴·출전 선택·전투 대사는 화면 안 자체 선택 창으로 표시하고 예/아니요는 원작 MARK 버튼 그림을 사용. 원작 화면 틀에서는 HUD 숫자·현재영토·장 표시줄과 타이틀 메뉴 글자를 원작 MAIN 글꼴(ALL_FONT.16P·HANKAKU.FNT)로 원작 위치에 그림. 대화창·명령 창의 테두리와 글꼴은 미복원. |
| 엔진 화면 | 기본 화면은 엔진 배치. 필드는 지도가 창 전체를 채우고 HUD가 떠 있는 카드로 표시되며, 전투는 15×10칸 지도와 사이드바를 쓰며, 상단 두 줄에 전투명·턴·날씨와 메뉴·승리조건·적 위협·속도·다음 부대·턴 종료 버튼을 둠. 하단 행동바에서는 현재 위치에서 행동·대기·취소와 범위 책략 실행을 마우스로 선택할 수 있음. 준비된 아군은 사이드바 목록에서도 바로 선택 가능. 사이드바에는 고르거나 가리킨 부대의 초상화·병과·레벨·상태와 병력·MP·사기·경험 막대를 담은 카드와, 전투 지도 크기에 맞춰 커지는 미니맵이 있음. 대화·선택·저장 질문·명령 창·도구상은 공통 디자인(`CanvasTheme`)으로 그림. 대화창은 말하는 인물의 이름표를 창 위 가장자리에 붙이고, 15pt 글자와 64×80 원본 크기 초상화를 쓰며, 아래쪽에 기록·자동·건너뛰기 버튼을 둠. 전투 지도에는 부대마다 병력 막대가 붙고, 혼란 상태인 부대는 '혼란' 배지를 달며, 행동을 마친 아군은 어둡게 그림. 이동·공격·지원 범위는 칸마다 둥근 타일과 바깥 테두리로 그리고, 부대를 고른 뒤 가리킨 칸까지 걸어갈 경로와 커서 칸을 보여 주며, 고른 부대는 모서리 표시로 나타냄. 턴 시작 알림(턴과 날씨)은 지도를 가로지르는 띠로 크게 표시. 병력이 바뀐 부대 위로 피해·회복 숫자가 떠올랐다 사라지고(확대 전투 화면에서 바뀐 값은 지도로 돌아온 뒤 표시), 우군·적군이 움직이는 동안 지도 위쪽에 '우군 행동 중'·'적군 행동 중'을 보임. 행동하지 않은 부대는 원작처럼 약 0.4초마다 두 장의 대기 그림을 번갈아 보임. '적의 이동'은 엔진 기본값이 '본다'라서 적이 움직이면 화면이 따라감(원작 새 게임은 '안 본다'). 기능 메뉴에 전투 속도(보통·1.5배·2배·3배, 확대 전투 화면 포함)를 더했고, 메뉴는 아이콘과 묶음 선을 쓰며 설정 줄은 현재 값을 보이고 클릭이나 ←→로 바로 바꿈. 상단 줄의 기능 옆에 남은 부대 수가 붙은 턴 종료 버튼을 두고, 부대 목록에서 혼란 상태나 행동을 마친 아군에 '혼란'·'완료'를 표시. 확대 전투 화면과 일기토 화면은 지도 영역 가운데에 맞추고 능력치는 이름·숫자·얇은 막대 행으로, 승리조건 창의 확인은 엔진 버튼으로 그림(원작 화면 틀에서는 원작 막대와 MARK 버튼). 보기 → 원작 화면 틀(⌘⇧F)로 원작 틀로 돌아갈 수 있음. 원작(VGA 640×480 안의 640×400)과 같은 정사각형 픽셀을 쓰고, 원작 1픽셀이 화면의 정수 개 픽셀이 되도록 키워 디더링 무늬가 고르게 보임(보기 → 창 꽉 채우기로 끌 수 있음). 창 크기 640×400·960×600·1280×800(⌘1~⌘3)과 전체 화면(⌃⌘F). 메뉴 막대는 게임(타이틀로 돌아가기, 불러오기 ⌘O, 저장 ⌘⇧S, 빠른 저장·불러오기, 대사 기록, 대사 자동 넘기기, 선택·전투 진입까지 건너뛰기, 빨리 감기, 적 공격 범위), 보기, 개발(연구 도구), 윈도우로 구성. 게임 규칙과 원작 그림은 바꾸지 않음. |
| 전투와 캠페인 연결 | 출전 선택·보존 부대의 재배치·승리 보너스·다음 전투 연결. 퇴장 이벤트 동안 물리 공격/반격/범위 책략을 중단·재개하며 공유 문맥과 새 대상 상태를 재조회. 전투 종료 뒤 원작 결과표로 스크립트가 고른 지도(09·11) 진입, 연속 전투 재진입, 패배 마스크, 재시작을 구분. 전투 메뉴의 총퇴각은 원작 36 체크포인트에서 그 전투를 다시 시작하고(연속 전투에서는 원작처럼 거부), 게임종료는 재시작 선택으로 이어짐. 패배하면 원작 MAIN의 재시작 선택(문구는 로컬 자료에서 읽음)을 띄우고 예는 새 캠페인으로, 아니요는 창 닫기로 처리. |
| 전투 그림·오프닝·엔딩 | 원본 전투 인물과 일기토 프레임을 로컬 해독. 일기토는 원작 순서대로 등장·돌진·합·도주·쓰러짐을 원작 틱과 효과음, 지형별 배경, 아래 두 정보 창과 함께 재생하고 그동안 일기토 음악을 틂. 오프닝 데모 전체(16장면), 엔딩 세 갈래(END1 두 종류, END2), 공통 크레딧을 원작 그림·글꼴·음악으로 재생. 원작을 실행해 비교하지는 않음. |

전투 화면은 지도를 클릭해 조작하고 방향키·휠·미니맵 클릭으로 시야를 옮깁니다.
공격·일기토·엔딩의 화면 전체와 원작 타이밍을 재현했다는 뜻은 아닙니다.
`--battle`은 독립 검증 상태입니다. 초기 플래그를 비운 배치의 캠페인 도달 여부는
실제 시나리오 입력 재생과 별도로 확인해야 합니다. 이전 `experimentalV1`은
`--experimental-rules`를 명시한 연구 모드에만 남아 있습니다.

강화한 시험 봇은 여러 시드와 분기에서 첫 전투부터 엔딩까지 도달했고, 전투 64개를 모두
지나갔습니다. 일반 수치로 사람이 끝까지 플레이한 검증은 아닙니다. 원작 세이브 다섯 슬롯도 모두 불러와 같은 방식으로 엔딩까지 이어졌습니다. 슬롯에 저장되지
않는 난수·전투 중 상태는 복원하지 않습니다([원작 세이브](research/original-saves.md)).

## macOS 빌드

Apple Silicon Mac, 설치된 Xcode Command Line Tools, Python3.11 이상이 필요합니다.
전역 패키지를 설치하지 않습니다.

```sh
python3 tools/build.py --game /path/to/original/GAME --verify --install
```

`--game`에는 `GAME/` 폴더가 든 원본 ZIP도 지정할 수 있습니다. DOS 프로그램은
실행하거나 수정하지 않습니다. 앱은 `build/Yeonggeoljeon Engine.app`, 설치 위치는
`~/Applications/Yeonggeoljeon Engine.app`입니다. 기존 연구 앱을 교체하기 전 ZIP 백업을 만듭니다.
이전 공개 엔진 기반 앱은 교체하지 않습니다.

제공된 판본의 `OPGRP.R3` 타이틀 영역은 손상되어 있습니다. 정상 자료를 보유했다면
`--title-opgrp /path/to/intact/OPGRP.R3`를 추가할 수 있습니다. 자동 다운로드는 하지 않습니다.

기본 화면은 원작 캠페인 실행기입니다. 타이틀 뒤 원작 메뉴에서 새로 시작하거나,
원작 저장 질문에서 만든 자체 엔진 저장 파일로 이어서 진행합니다. 저장 파일은 기본적으로
`~/Library/Application Support/Yeonggeoljeon Engine/Saves`에 두며, 환경 변수
`YEONGGEOLJEON_SAVES`로 다른 폴더를 지정할 수 있습니다.

캠페인 창의 엔진 추가 단축키는 다음과 같습니다. A 또는 ⌘E로 대사 자동 넘기기, S 또는 ⌘K로 선택·전투 진입까지
건너뛰기, Control을 누르고 있으면 빨리 감기, L 또는 ⌘J로 대사 기록, F5 또는 ⌘S로 중단 저장, F9 또는 ⌘L로 중단한 게임 이어하기, ⌘T로 빨리 감기 고정입니다. 전투에서는 D 또는 ⌘D로 적 공격 범위를
켜고 끄며, Tab과 Shift-Tab으로 아직 행동하지 않은 부대를 차례로 고릅니다.
**중단 저장**은 일반 슬롯과 별도의 한 칸에 저장한 뒤 타이틀로 돌아가는 기능입니다. 전투 도중의 병력·행동 여부·이동 취소 원점·난수와 필드의 대사·선택 상태를 보존합니다. 한 번 이어하기에 성공하면 중단 파일을 소모하고, 복원에 실패하면 파일과 현재 플레이를 유지합니다. 여러 저장 지점을 쌓거나 같은 파일을 반복해서 불러오는 흐름을 줄이기 위한 편의 기능이며, 외부 파일 복사를 막는 기능은 아닙니다.

플레이 중 언제든 중단 저장을 요청할 수 있습니다. 공격·이동 연출이나 적 턴은 처리가 끝난 다음 수동 입력 경계까지, 상점·출전·도구 선택과 진행 중인 이벤트는 현재 처리가 끝날 때까지 기다립니다. 대기 중 F5를 다시 누르면 예약을 취소합니다. 타이틀·엔딩 화면과 오류로 멈춘 상태는 저장하지 않습니다. 일반 슬롯은 마을·세계지도에서 ⌘⇧S로 저장하며, 이전 빠른 저장 파일은 **이전 빠른 저장**이라는 이름으로 계속 불러올 수 있습니다.

자동 저장과 이전 빠른 저장은 불러오기 목록에 함께 나옵니다. 전투 오프닝이 끝나면 첫 턴 직전 상태를 별도 **전투 시작** 슬롯에 자동 저장합니다. 이 슬롯은 해당 전투의 첫 턴부터 재개하며, 중단 저장과 구분됩니다. 자동 저장에 실패하면 화면에 알리고 재시도하며, 저장되었다는 안내는 쓰기에 성공한 경우에만 표시합니다. 마을·세계지도에서 Esc는 메뉴를 엽니다. 전체 조작은 **도움말 → 플레이 안내(⌘/)** 에서 확인할 수 있습니다.

저장·불러오기와 중단 저장의 확인·오류 안내는 게임 안의 공통 메뉴를 사용합니다.
타이틀의 **이어하기**, 메뉴 막대의 **불러오기(⌘O)**, 전투 **메뉴 → 불러오기**에서
같은 슬롯 목록을 엽니다. 자체 저장·중단 저장·원작 슬롯을 함께 고를 수 있고, 원작
슬롯은 읽기 전용입니다. 전투에서는 명령을 기다리는 시점에 목록을 열 수 있습니다.
중단 저장 확인창을 취소하면 기존 대사·선택과 남은 표시 시간이 그대로 이어집니다.

대사 건너뛰기는 새 전투 맵에 들어올 때 멈춥니다. 사수관을 포함한 전투 소개 대사는
일반 대사처럼 표시되며, 소개 중 다시 S를 누르면 다음 선택이나 명령 차례까지 넘깁니다.
건너뛰는 동안에는 문장 전체를 즉시 보여 주어 빈 대사창이 나타나지 않으며,
도중에 건너뛰기를 꺼도 이미 표시한 문장은 그대로 남습니다.
메뉴 **개발 → 원작 캠페인 실행 연구**에서 새 실행 창을 열 수 있습니다. **원작 전투 복원 검증**에서는
독립 전투를 엽니다. 클릭으로 선택·이동·공격합니다. Return은 행동할 부대를 고르거나 현재 위치의 명령 창을 열고, Space는 선택 부대를 대기시킵니다. 턴 종료는 화면 버튼이나 메뉴를 사용하며, Esc·오른쪽 클릭·Backspace로 이동을 취소합니다. 명령 창의 책략 버튼으로 사용 가능한 명령을 고르고
대상을 지정합니다. 범위 책략은 하단의 실행 버튼 또는 Return으로 확정합니다. 이름 표가 연결되지 않은 책략은 ID와 MP 비용으로 표시합니다.
**책략 습득표**에서는 장수의 현재 병과를 기준으로 이미 배운 책략과 앞으로 배울 책략의 습득 레벨·필요 MP·효과·대상·사용 조건을 확인할 수 있습니다. 사거리는 시전자, 적용 범위는 선택 대상 또는 시전자를 중심으로 각각 격자에 표시합니다. 색 칸은 범위, 흰 점은 기준 위치입니다. 마을·세계지도에서는 **장수 → 장수 정보 · 책략 → 장수 선택**, 전투에서는 장수의 **명령창 → 책략 습득표** 또는 **메뉴 → 책략 습득표**로 엽니다. 아직 배우지 않은 책략도 선택해 읽을 수 있으며, 조회는 행동과 MP를 소모하지 않습니다. 전직하면 현재 병과에 맞춰 목록이 바뀝니다.

**전투 재생 배속**은 지도 이동·공격·책략·일기토 등의 연출을 함께 빠르게 하고, **지도 이동 속도**는 부대가 지도에서 걷는 속도만 조절합니다. 두 설정은 함께 적용되며 이동력이나 전투 결과를 바꾸지 않습니다. 설정 메뉴에서 항목을 선택하면 차이를 설명하는 안내가 나타납니다. **확대 전투 연출**은 교전 화면 표시 여부, **적 이동 따라가기**는 적 이동 중의 화면 추적 여부입니다.

전투 **메뉴 → 전투 결과 기록**은 현재 전투의 공격·반격·책략·도구 결과를 최신 순서로 보여 줍니다. 확정된 피해·회복·사기 변화·실패·혼란·퇴각을 최근 500건까지 보관하며, 중단 저장 후 이어하기에도 유지됩니다. 새 전투나 재시작에서는 새 기록을 시작합니다. 스크립트가 직접 바꾸는 병력·상태와 이야기 대사는 이 기록의 대상이 아닙니다.

전직·병종 변경 도구를 사용하면 **전직 전후 비교**에서 현재 레벨·사기·장비를 기준으로 공격력·방어력·최대/현재 병력·최대 MP·이동력·공격 범위, 지형별 이동과 책략 습득 변화를 먼저 확인합니다. 목록 선택은 조회만 하며, 하단 **전직** 버튼을 눌러야 도구와 행동을 소모합니다. 키보드는 ↑↓로 비교하고 Tab으로 버튼을 고른 뒤 Enter로 확정하며, Esc는 취소합니다.
캠페인의 현재 미지원 경계는 화면에 표시합니다.

## 소스 검사와 로컬 진단

```sh
python3 -m unittest discover -s Tests -v
swift run yeonggeoljeon-engine --self-test
python3 tools/audit_source.py --output build/source-audit.json
python3 tools/source_release.py
```

실물 검사는 `ORIGINAL_GAME_DIR`, 선택 타이틀 검사는 `TITLE_OPGRP_FILE`을 명시해야
실행됩니다. 건너뛴 실물 검사를 통과로 계산하지 않습니다. GitHub CI는 원작 자료를
보관하거나 다운로드하지 않습니다.

```sh
swift run yeonggeoljeon-engine --data /path/to/GameData --battle 0:0:5
swift run yeonggeoljeon-engine --data /path/to/GameData --verify-battle --battle 0:0:5 --output /path/to/new-battle-report
swift run yeonggeoljeon-engine --data /path/to/GameData --verify-vm --output /path/to/new-campaign-report
swift run yeonggeoljeon-engine --data /path/to/GameData --verify-play --inputs /path/to/local-inputs.json --output /path/to/new-play-report
swift run yeonggeoljeon-engine --data /path/to/GameData --verify-play --resume /path/to/native-save.json --inputs /path/to/rest.json --output /path/to/new-resume-report
swift run yeonggeoljeon-engine --data /path/to/GameData --list-campaign
```

출력은 입력과 분리된 빈 폴더여야 합니다. 전투 진단의 아군 입력은 검사 드라이버가
생성하며 원작 AI로 주장하지 않습니다. 캠페인 진단은 대사·이동을 진행하다 원작
이벤트·선택·미지원 경계에서 멈추며 승리나 다음 장면을 주입하지 않습니다.

현재 실제 원본 검사에서는 명시한 플레이어 입력41개로 첫 전투의 원작 일기토·승리
이벤트를 거쳐 다음 장면으로 복귀하고, 두 번째 전투의 수동 조작 단계까지
이어졌습니다. 2026-11-07 재검사에서는 정상 수치와 합법 입력 796개로 새 게임부터
사수관·호로관·신도·청하·계교·북해의 여섯 전투를 승리해 서주의 전투(1:1:5) 시작까지
진행했습니다. 실제 상점 구매와 보유 회복품 사용을 포함하며, 공개 재생기로
796개 입력이 모두 정상 처리되는 것을 확인했습니다.
능력치·좌표·승리·플래그를 검사기가 주입하지 않은 경로이며, 이 결과는 후반이나
전체 캠페인 완주 검증을 뜻하지 않습니다.
도달한 세 전투의 첫 턴 직전 상태를 JSON으로 저장하고 다시 읽어 이어 진행한 결과,
관측 기록과 최종 상태(재구성 시 폐기하는 화면 명령 커서 제외)가 끊김 없이 진행한
결과와 같았습니다. 별도 219개 입력 경로에서는 신도 승리 후 거록 전투에 진입했습니다.
그 경로의 신도에서 전투 기록 8건을 포함해 중단 저장을 JSON으로
왕복한 뒤, 남은 정상 입력 87개를 같은 순서로 적용해 게임 상태·난수 상태·전투 기록의
일치를 확인했습니다. 이 실제 경로의 기록 종류는 공격과 퇴각이며, 책략과 도구는
별도 합성 검사로 검증합니다. 이 세 전투에는 아군 배치를 유지하는 연속 전투가
포함되지 않습니다. 입력 경로와 화면·대사
보고서는 로컬에만 보관합니다. 플레이어 입력을 고른 검사 정책은 원작 AI가 아니며,
적과 비수동 아군의 행동은 복원한 엔진이 처리합니다. 원본69개 파일의 해시 불변과
원작 없이 실행하는 합성 검사를 별도로 확인했습니다.

별도 후반 검사에서는 호출자가 지정한 원본 4번 저장을 저장된 수치 그대로 불러와
정상 입력 592개로 제3장 서릉의 전투(3:4:4)를 27턴에 승리하고, 전후 장면과 화목
선택을 거쳐 제4장(4:0:4:12)에 진입했습니다. 처음부터의 무중단 재생과 중단 저장을
이용한 경로의 최종 게임 상태·난수 상태·전투 기록 223건이 모두 일치했습니다.
이어지는 23개 입력까지 합친 총 615개를 다시 재생해 양양의 전투(4:0:5) 진입과
최종 상태·난수 상태 일치를 확인했습니다. 양양에서의 전투 행동은 검사하지 않았습니다.
다른 경로에서는 공격·책략·회복·퇴각과 40턴 제한 패배, 재시작 선택까지의 정상 입력
615개를 재생했습니다. 기록 9건을 가진 중단 파일에서
나머지 536개 입력을 적용한 결과도 게임 상태·난수 상태·최종 기록 106건이 같았습니다.
이 두 검사는 새 게임부터의 연속 완주를 증명하지 않습니다. 원본 1번 저장은
제4장 마지막 전투가 끝난 엔딩 직전 상태여서, 엔딩 진입 검사에만 사용했습니다.

수학·정수 폭·난수 호출·형식의 정적 복원 및 새 코드 검사는 DOS 원본 런타임과의
비교와 다릅니다. 고정 진단 seed1, 전체 난수 시간축, 실제 OS 입력, 원작 화면의
픽셀 일치, 전체 캠페인 완주를 서로 구분합니다. TF-DCE 그림은 명시적 zero-plane
바탕을 사용하며 원본의 보존 plane 정보도 로컬 메타데이터에 남깁니다.
